# Schema 3 Runtime workflow

## Startup and authority

1. Run `python3 scripts/ai_ppt_runtime.py preflight`.
2. Create with `create_ai_ppt_project`, or omit `projectRoot` to resume the latest schema 3 project.
3. Keep every project, artifact, review resource, render, PPTX, target export, and experience record below the configured managed Runtime root.
4. Call `get_ai_ppt_project_snapshot` after every write and retain `revision`.
5. Call `get_ai_ppt_project_status` for the user-facing state; do not derive status from Gate names or UI state.

The Runtime never falls back to an old state/projection. Legacy projects are available only through explicit one-way import; missing evidence remains unproven.

## Formal write groups

- Project and Mission: `add_ai_ppt_material`, `save_ai_ppt_mission_draft`, `confirm_ai_ppt_mission`, `set_ai_ppt_release_target_policy`.
- Formal work: `request_ai_ppt_agent_action`, `submit_ai_ppt_human_decision`, `commit_ai_ppt_artifact`.
- Content: build the four objects, run two hard gates, repair, save page decisions, submit or withdraw a Batch, confirm a revision plan, and create a change set.
- Review: `open_or_resume_review_session`, `record_review_host_open_receipt`, `record_review_host_notification_receipt`, and `record_review_ai_receipt`.
- Visual feedback: `submit_visual_anchor_feedback_batch` and `save_visual_contract_review_marks`.
- Gates and delivery: `record_internal_gate`, `confirm_ai_ppt_gate`, `record_chat_delivery`, `close_ai_ppt_project`, `abort_ai_ppt_project`, and `reopen_ai_ppt_scope`.
- Experience: `recommend_experience`, `record_experience_application`, and `summarize_project_experience`.

Every write uses `expectedRevision` and an idempotent command identity. Domain services recheck current heads and Gate preconditions. On `REVISION_CONFLICT` or `REVIEW_SOURCE_STALE`, refresh first and preserve user drafts.

The formal semantics are stricter than the tool names:

- `MissionConfirmation` is created only after the complete current task, material inventory or explicit no-material choice, background, constraints, red lines, and unknowns are shown and the host verifies the current confirmation action. Intent words are never evidence, and ordinary conversation or a stale card cannot confirm.
- `save_content_page_decision` silently persists one current-source `PageDecision` plus its required non-approved comment. It sends no follow-up, changes no content, and confirms no Gate. Only one complete immutable `ContentReviewBatch` starts concentrated processing.
- The chief saves one whole-deck revision plan; user confirmation is required before applying it. Every new source version receives full re-review with no inherited approvals.
- Visual ReviewMarks bind exact field/text anchors, prefix, suffix, comment, source version, and revision. A stale anchor conflicts; saving marks never confirms G3.
- `record_internal_gate` is restricted to authorized G1/G2 reviewers and exact current evidence heads. `confirm_ai_ppt_gate` accepts only G0/G3/G4, resolves the exact current source version, revision, evidence refs, and single-use challenge, and requires a verified current user action or fresh host-native confirmation. `MissionConfirmation` never confirms a Gate.

One Agent turn stops at the next later user Gate unless a new host verification or elicitation result arrives after the current review source is published. Never replay an older message or infer a Gate from task or Mission approval. `HOST_CONFIRMATION_NOT_COMPLETED`, `HOST_CONFIRMATION_DECLINED`, and `HOST_CONFIRMATION_UNAVAILABLE` cause zero Gate business writes and preserve earlier user decisions. An accepted form with its confirmation unchecked is incomplete, not a revocation. Timeout/cancellation must invalidate the pending request so a late response cannot write; do not automatically open a replacement form or fall back to another transport. A real verified receipt is still required after any source-only repair.

## Mission and content source replacement

Save `MissionDraft` → show the current complete card → recognize intent only in that card's sole-pending-action context → obtain verified or host-native confirmation → create `MissionConfirmation` → pass the Python content precondition → build the four content objects. `materials-provided` binds the current material inventory; `no-materials-confirmed` binds the current empty-material identity. `PresalesEvidenceBook` then classifies the work as `material-backed`, `mixed-evidence`, or `proposal-led`.

Formal content task creation and formal content artifact commit both recheck that Python precondition. Node, React, Browser, prompts, fixtures, and adapter calls cannot bypass it. Across all modes, preserve `来源事实`, `材料推断`, `用户已确认`, `诊断假设`, `方案建议`, `待联合验证`, `证据缺口`, and `禁止使用`. Missing evidence does not block complete content work; invented customer facts, numbers, cases, capabilities, results, or commitments always fail.

A new Mission, material inventory, or `ReadingDeckBlueprint.source_version` preserves immutable history but atomically removes stale current confirmation, review, visual, delivery, completion, and queued Agent heads as applicable. It reopens G0 and locks G1–G4. Old artifacts remain readable but cannot authorize new writes.

### Derived source finding registration

Use existing `add_ai_ppt_material` with `materialType="finding"`, `materialInventoryRef`, `sourceId`, `sourceSha256`, `sourceLocation`, `contentKind` (`text`/`image`) and `exclusionMode` (`scope`/`image-content`, the latter only for images). These are closed finding fields; do not mix file-import fields, caller content hashes, or arbitrary artifact kinds. `projectRoot/expectedRevision` remain the public request identity; the bridge derives the command identity, and replaying the exact original request/revision reuses it. The fixed derived artifact is created transactionally after current-source extraction. It preserves all existing business heads and Gates; re-registering the inventory is a different operation that invalidates Mission/content.

EvidenceBook declared and excluded findings must independently resolve against current real source bytes; DecisionContext, Fit, Blueprint and hard gates repeat the source preflight. A declared page and an excluded object on it can coexist: reference validity does not authorize sending an intersecting whole-page atom. All exclusions still block intersecting source scopes. Explicit image-content exclusions also replay the excluded image and compare actual candidate image bytes, so identical media under another object or source cannot escape. Scope-only exclusions do not acquire a cross-source content ban, and text similarity is not an exclusion mechanism. Invalid exclusion extraction fails closed; never omit an unreadable exclusion to proceed.

## Image 2 configuration and no-generation preflight

Host configuration uses `AI_PPT_IMAGE2_ADAPTER_COMMAND`, `AI_PPT_IMAGE2_RECEIVER`, `AI_PPT_IMAGE2_MODEL`, and optional `AI_PPT_IMAGE2_ADAPTER_ENV_ALLOWLIST`. The manifest declares forwarding; it does not install values or prove the running process has them. Image 2 is the page-design role; the exact receiver/model must match the approved scope and policy. The current minimal production loop defaults to and exposes only `CRS / gpt-image-2.5-sunburst` for new generation. The older Image 2 form remains recognized solely to read and recover historical identities without relabeling; it is not a current new-request option. These are the recognized exact JSON argv identities:

| Status | `AI_PPT_IMAGE2_MODEL` | Exact `AI_PPT_IMAGE2_ADAPTER_COMMAND` argv |
| --- | --- | --- |
| current new-generation route | `gpt-image-2.5-sunburst` | `[current Python, current package wrapper, "--model", "gpt-image-2.5-sunburst"]` |
| historical identity only | `gpt-image-2` | `[current bridge sys.executable absolute path, current package image2_crs.py absolute path]` |

Use the four-item Sunburst command for every new request. The old two-item command may appear only while reading or recovering an existing old-model identity; it cannot authorize a new request. A two-item command with the new model label, the new command with an old payload, other models including Flare/`latest`/generic aliases, extra arguments, and lookalike wrapper paths are rejected. Never execute an unknown command to discover its behavior. Preflight only appends `--preflight` to a recognized command. The wrapper CLI remains able to parse historical `[]`/`[--preflight]` and current `[--model,gpt-image-2.5-sunburst]`/`[--model,gpt-image-2.5-sunburst,--preflight]`; parser compatibility does not expose the old route for new work. There is no shell or permissive argument parser. Keep credentials out of argv, public input, Runtime files, prompts, and diagnostics. The fixed helper manages credentials in memory during generation; no extra credential environment names are required. This adaptation does not change TLS, helper, loader, or installed caches.

Call current-host `get_ai_ppt_project_snapshot` with optional `includeImage2Preflight=true`. Default snapshots retain their existing shape. The additional closed `image2_preflight` reports safe configuration presence, known-wrapper recognition, protocol status, helper executable availability, and nonce/code identity. Match the wrapper hash to the reviewed package and retain the current nonce. Unknown command argv is unsupported and never launched. The recognized `--preflight` branch checks local protocol and helper executable status; it never executes or reads the helper, calls the network, or creates business tasks/artifacts/events/revisions. Missing capability does not revoke existing user decisions. `external_connection=not-tested` is a required proof limit.

Keep transport/preflight v1/v2 for the current Sunburst route and historical identity reads. V2 requires the existing closed preflight/v2 response with the required `generation_protocol=image-led-image2-transport/v2`; v1 readiness cannot substitute for it, and no v3 is introduced. Verify the model across configured command, payload, and probe as well as the scope/grant/policy/pack reference chain before queuing or sending. Never relabel an old grant or rewrite confirmed copy, G0, material exclusions, or common design rules to migrate the model. Use formal matching authorization records while preserving applicable existing user decisions; do not add per-page permission.

Pre-selection repair remains a historical `CRS / gpt-image-2` capability and is not exposed by the current Sunburst-only minimal loop. A current Sunburst candidate that needs another design must use a fresh explicit new-generation request with a fresh ID and the unchanged confirmed source inputs; it cannot fall back to Image 2 or relabel the old repair transport. For historical recovery only, existing preflight/v2 must explicitly echo `image-led-image2-repair-transport/v1`; ordinary v2 readiness does not suffice. The payload has exactly `payload_version,receiver,model,base_payload,edit_target,issues`. `base_payload` is the complete unchanged current original input/v2; `edit_target` is server-derived from a formally bound completed PNG response and has exactly `role="edit-target",image_sha256,data_base64,mime_type="image/png",width,height`. Its independent diagnosis must have passed the exact source-image exclusion check before any repair queue or external send. See [the formal repair result and action sequence](visual-workflow.md#c2-production-entries). No free instructions, observed text, exclusion explanation, private ledger or internal references enter the provider text. The target is image 1; original image material numbers and semantic material uses both shift by one, preserving original material bytes/order/roles. A current diagnostic plus explicit new request ID is required; the request and response keep original pack, diagnostic, source response and complete repair payload hash. Historical recover reads the original identity even after a later diagnosis or revocation, with no new write or resend. Full decoding and output fitness unwrap the original base, and new output must pass its own complete downstream checks.

Generation uses the existing single-request Runtime route with the exact compiled payload: JSON without input images, multipart for ordered image bytes, no C1 prompt/template reuse or local-path metadata. Wrapper header/MIME checks complement the compiler and Runtime's full image decoders. The wrapper performs one helper call and one HTTP attempt, without retry, redirect, endpoint fallback, or URL-image download. Helper timeout is 30 seconds, probe timeout 10 seconds, and HTTP timeout 300 seconds per blocking socket operation; none promises provider exactly-once behavior or a total-duration bound. Transport or invalid-response failures remain unknown in the existing ledger; a decoded original that fails output fitness is completed with needs-revision usability instead. Recover the original `generationRequestId` using `generationIntent=recover`; only a new explicit design request permits `generationIntent=new`. Local response hash receipts are local identities only.

The existing-deck `source-media-guided` mode is an explicit multipart case under the same transport. It replays only current source-page PNG/JPEG bytes whose page and hashes are authorized and not excluded. It also derives source placement from one explicit slide size and each picture's explicit transform, stores object identity locally, and sends only ordered public image numbers plus normalized position/role wording. Missing geometry, changed bytes, exclusions, or mismatched order fail before Runtime write or HTTP. A request may additionally carry complete `source_media_role_bindings`: each guided picture object is bound exactly once to one to four current same-page non-title text identities, while provider text receives only the public image number and exact source wording. Partial coverage, duplicate/unknown pictures, invalid text identities, or bindings on another layout mode fail before registration; requests without this optional field retain their original identity and replay behavior. Its independent review targets the exact request and response and requires media-fidelity and role-placement checks. Blank-slot/local-composition requests keep `materials=[]`; they cannot be relabeled as guided after generation. A new request may carry `required_visible_item_ids` only for exact current non-title source text identities. Runtime canonicalizes them in source order and derives a fixed instruction that each original string must be a separate visible structure; unknown, duplicate, title, or cross-page identities fail before registration. No free-form revision text or common-rule mutation is allowed.

`single-main-screenshot-focus` is a no-source-bytes layout for a page whose exact current media inventory contains one evidence-bearing business screenshot and otherwise only decorative background or production strips. Registration requires `main_source_picture_object_id` and revalidates that identity against the current page. Runtime reads the exact current screenshot locally, derives its pixel dimensions and reduced aspect ratio into `main_screenshot_spec`, and recomputes the same spec whenever the request is read or recovered; neither bytes nor internal object identity enter provider input. The provider receives a fixed instruction to design one large blank main-screenshot region close to that aspect ratio while keeping all copy, capabilities, hierarchy, routes and relations as text and structure; it must not create picture slots for those nodes. The blank region itself must use at least 50% of both the full-canvas width and height, favoring a left or central screenshot with structure to the right and bottom rather than a wide shallow strip. The eventual `contain` result must use at least 45% of the full-canvas width and 35% of the full-canvas height and remain the page's primary visual focus. Local composition uses `single-main-screenshot-focus-compositor/v1` with exactly one `place-main-source-screenshot` operation and fixed-reason `exclude-source-media` operations covering every other current-page picture. The main screenshot uses `contain`; the compositor calculates the effective displayed dimensions with its actual padding and rejects an undersized wide-shallow or narrow-tall region before writing. The region remains bounded and cannot replace the whole slide. Review binds `[request_ref,response_ref,composition_ref,target_image_ref]` and requires the patched checks including `source-media-disposition`. The used-media set must be exactly the bound screenshot and the excluded set exactly all remaining current-page media; only the bound screenshot enters TargetBinding material roles.

Historical designs use the separate local-only `historical-design-import/v1` route. Bind exact PNG/JPEG bytes, current source-deck/page/copy/rules identity and historical `CRS / gpt-image-2` request/response provenance. The Runtime atomically records a completed request/response pair without transport. Never execute that record, relabel it as Sunburst, remove a same-page unknown/started request, or select it without the normal source review. When the historical composition is already source-faithful, review the exact request and response for media fidelity and role placement. When its structure is reusable but generated stand-ins must be replaced by exact source photos, logos, or screenshots, register one reproducible `historical-design-source-replacement/v1` composition before review. Use only bounded `replace-source-region`, governed source-media exclusion, small `mask-region`, and exact calculated `page-marker` operations; every source image needs one use or exclusion disposition and the touched area cannot approach a whole-slide rewrite. The independent review must target `[request_ref,response_ref,composition_ref,target_image_ref]` and include `source-media-disposition`; TargetBinding includes only the source media actually inserted into the exact target image. Native-only corrections must remain source-backed and explicit; they cannot become a hidden redesign.

The public existing-deck status recovery entry is `recover_existing_deck_image_request`, mapped to `optimization-recover-request`. It accepts the original project/request identity and intentionally has no `expectedRevision`: the Runtime reads the persisted response artifact without constructing `Image2CommandAdapter`, contacting the provider, retrying, or writing state. Return the persisted `started`, `unknown`, or `completed` record exactly; when no response was persisted, fail instead of fabricating one. A `started` or `unknown` readback never permits a replacement request ID or proves remote completion. Use a new ID only for a separately authorized new design after the applicable supersession rules are satisfied.

Both HTTP paths use the current strictly selected Sunburst model and request targets `2048x1152 / high / output_format=png / n=1`. One image uses `image`; two images use ordered `image[]` with their original bytes. An optional material pool may be unused in the final design, but images in the input cannot be dropped to avoid edits. Current new generation accepts exact `gpt-image-2.5-sunburst` reports only. Historical `CRS / gpt-image-2` observations remain readable with their original `gpt-image-2` / compatible `gpt-image-2-codex` semantics, but do not expose a new-request route. Every explicit root or image model must be allowed for its bound identity; one valid field cannot hide another invalid field. The original transport model still equals the requested route. An invalid report, invalid observation, or changed transport route is rejected after the HTTP attempt, remains unknown without retry, and is never counted as zero HTTP.

Known CRS command v2 returns a required closed `provider_observation`, carried through normalized output: `version=image-led-provider-observation/v1`, `reported={response:{},image:{}}` with each origin preserving only present model/quality/size/output_format fields. Current Sunburst uses `model_match=exact|not-reported`; `compatible-image2-codex` remains historical Image 2 semantics only. Keep `independent_engine_proof=false`, actual HTTP `response_sha256`, and local UTC `observed_at_utc`. Do not fill absent fields from request targets, relabel reports, trust a supplied match classification, or accept missing/mutated observations as a v1 fallback. Historical v1 six-field replies and legacy two-field injected results remain readable; record observations only when actually supplied and validated. A compatible report is not independent proof of the upstream engine.

The provider prompt separately adds fixed `system_output_requirements={version:"image-led-system-output/v1",canvas:{aspect_ratio:"16:9"}}`. It leaves the original v2 input/schema, customer common_rules.background, copy/page_goal/materials, input hash, grants, and G0 unchanged. This system output requirement specifies canvas proportion only, not body composition. Request targets and reported metadata cannot replace the actual image result: Runtime fully decodes and preserves original bytes with actual image_size/MIME/hash.

For the current Sunburst route and historically readable CRS v2 outputs, `image-led-output-fitness/v1` requires `abs(16*h-9*w)<=8` and `w>=1280 && h>=720`, using decoded width/height. The ratio tolerance represents rounding integer height by at most half a pixel; it is not a percentage tolerance or an allowlist for one returned size. This minimum is technical raster fitness, not text readability, design quality, or user acceptance. A legal decoded image that fails fitness is still completed and preserved, with current usability needs-revision; candidate registration and selection recheck the original image and block unsuitable results. Missing or changed observations cannot bypass geometry. Do not resize, crop, resample, or rewrite dimensions to make an output appear compliant; downstream native conversion continues to use actual source-image proportion and geometry.

Controller-authorized online component verification follows the current exact Sunburst route using the reviewed actual wrapper with a purely local valid v2 envelope and non-customer synthetic text/images; it needs no fabricated Runtime, G0, grant, or acceptance and reads no customer material. The current required request shapes are zero-image generations and two-image edits at the request targets; one-image multipart is covered offline and a live one-image call is optional, not an additional customer prerequisite. Preserve each historical artifact under its original route identity. Real HTTP, reported metadata, full result decoding, output fitness, the formal Runtime, and real three-page customer acceptance are separate evidence. This source task performs no real HTTP/helper, installation, or customer access. The C2 verification ledger is the authority for source verification, independent review, and subsequent runtime states; do not infer installation, release, or customer readiness from this reference.

## Gate meaning

- G0: current two-hard-gate-passing `ReadingDeckBlueprint`, one complete all-approved content review Batch, and explicit user confirmation.
- G1: complete `DeckDesignSystem` plus all `SlideVisualContract` objects pass internal contract checks.
- G2: native anchors and all targets required by the current immutable `ReleaseTargetPolicy` pass semantic, aesthetic, engineering, and named-target-render checks against one PPTX hash. Deferred profiles are not Gate rows and do not imply compatibility.
- G3: current complete visual review source plus explicit user confirmation.
- G4: current full-deck build, QA, new final-PPTX evidence for every policy-required target, delivery package bound to the re-resolved current policy, verified sent-file receipt, and explicit final confirmation. G2 anchor evidence cannot be reused.

## Review and capability boundary

Create one current ReviewSession per review type and source identity. Internally retain the complete `ReadingDeckBlueprint`, but expose content pages only through the accepted `ContentReviewPageViewModel`; backend notes, evidence identities/source-entry UI, mappings, relations, reading-quality catalogs, and other internal fields do not become content-review modules. Let the host create its authenticated Review Bridge resource and open only that resource in the Codex built-in Browser at 760/1000/1440px. The Bridge resolves current project, source version, and revision from Python authority; the page cannot choose them.

Reliable persistence, host open, host notification, and AI receipt are independent. A `review-session-ready` response is only a handoff: immediately open its scoped URL with the Agent's Codex built-in Browser and do not claim success before actual navigation. Missing stdio adapter injection is not Browser unavailability. Report `BROWSER_REVIEW_UNAVAILABLE` only when the Agent Browser is absent or scoped navigation fails, and `BROWSER_REVIEW_SAVE_UNAVAILABLE` only when Review Bridge/Python persistence is unreliable. Preserve Runtime state, last valid artifacts, and drafts. A fixture, local preview, generated URL, loopback request, or Browser render cannot prove a real host action.
