# AI PPT Studio｜产品代码指引

## 目录身份

本目录是源码根目录，包含运行时代码、测试、Skill、插件与 Widget 的未来实现、历史规格以及产品原型。Git 项目根目录和权威产品基线位于上一级目录。

开始任何实现前必须依次读取：

1. `../00-唯一研发基线索引-v1.0.md`
2. `../01-产品需求基线-v1.0.md`
3. `../02-系统详细设计-v1.0.md`
4. `../03-UI设计与交互规范-v1.0.md`

## 实现边界

- 需求、系统合同与 UI 行为以父目录四份基线为准；本目录历史规格只作低优先级实现记录。
- 源码、测试和构建命令以本目录为工作目录运行。
- PPT 运行数据只写入默认 `/Users/defei/Documents/AI-PPT-Workspace`，不得写进源码或产品基线目录。
- 并行 Web 产品空间为 `../../PPT  web app `，未经用户明确授权不得回写。
- Image 2 承担整页设计责任；用户定版后的确切图片及绑定文案约束全部下游。Codex Presentations 只做忠实的原生可编辑转换与检查，不得重新设计、删改内容或静默回取旧文案；定版内容、设计还原、编辑性与跨页一致必须分别验证。
- 任何实现必须沿用唯一 `TargetBinding`（项目、页号/页序、定版图 hash、定版可见文案 hash、材料角色、已接受差异）；不得按文件名、目录顺序、相似度、旧 frozen 文案或模型猜测选标的。绑定或区域映射不完整时在写入前失败，跨页共同规范不能反向重排单页定版图。
- 任何会改变产品需求、交互合同或交付标准的技术发现，先回到父目录更新基线，不得只在代码里改变产品行为。
- C2 在其独立分支和 Worktree 中按主计划 §12.2 的最新授权实现；原子材料是内部切片。输入包复用既有材料和证据、核对实际 hash 与有效使用范围，不把格式校验或独立 validator 说成生产请求已受保护。

## 验证

Python 运行时的最低回归命令：

```bash
python3 -m unittest discover -s tests
```

修改产品文档或原型引用时，还必须从父目录验证所有 Markdown 相对链接。
