# Professional review and feedback

## Two governed review surfaces

Content review uses the real Codex sidebar at the host's maximum available width. It shows every page's neutral title, reading question, complete visible copy, speaker notes, identity, real evidence, source location and use, problem-solution mapping, reading quality, page relations, PageDecision, and immutable batch state. The content Browser is read-only evidence assistance.

G3 visual review uses the Codex built-in Browser and adds the Deck framework, Deck Design System, native anchor identity, current `ReleaseTargetPolicy`, required target evidence identities, explicitly deferred profiles, and every page implementation/acceptance field. Deferred rows never display a hash, pass state, or compatibility claim.

The source projection is authoritative. React never summarizes away contract fields, invents a passed status, or stores business state locally. `save_content_page_decision` is a silent page save: it never changes content, triggers Codex, or confirms G0. Only one complete immutable review batch triggers concentrated processing. The chief returns a deck-level revision plan, the user confirms it, and every new source version starts full-deck review with no inherited approvals. Saving one exact G3 mark records `field_anchor`, `exact_text`, `prefix`, `suffix`, `comment`, and `source_version`; it never confirms G3.

## Change scope and recovery

Interpret feedback as whole deck, chapter/page family, page, or element. Preserve raw wording separately from diagnosis and recommended action. Store target refs, preserve refs, previous/current versions, scope, evidence, decision, and result.

- Mission, audience, fact, narrative, or material change reopens G0.
- Full visual contract change reopens G1.
- Native/editability/target defect reopens G2.
- User visual decision change reopens G3.
- Full-deck/local delivery defect reopens G4 unless its root cause belongs earlier.

Do not reopen unrelated accepted work. Revision/source conflicts preserve drafts; network/save failure does not display a saved state.

## Learning boundary

Preserve raw feedback separately from the reusable mechanism. One clear, valid reaction may immediately create or update `same-type` experience and influence the current remaining work. It becomes `global` only when the user explicitly declares global scope or the same mechanism succeeds in at least two distinct type signatures with applicable hard-gate and user evidence.

Content and visual feedback both enter learning. After G4, formal close, or abort, automatically create `ProjectExperienceRetrospective`. Sanitize customer-specific facts and assets before persistence; keep counterexamples, scope, exact version, application/evaluation evidence, demotion, and rollback support.
