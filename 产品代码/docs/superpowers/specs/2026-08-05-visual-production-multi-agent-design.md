# AI PPT Studio 视觉设计多智能体架构设计

**日期：** 2026-08-05

**最近更新：** 2026-08-06（严格路线 B 与目标 PowerPoint 实机治理）

**状态：** 已批准，待研发实施

**适用范围：** G0 之后的视觉构想、整套设计系统、逐页视觉合同、严格路线 B 原生锚点页、目标 PowerPoint 实机验证、G1/G2 内部质量门与 G3 用户确认

**权威输入：** 项目根目录四份唯一研发基线；发生冲突时以更新后的产品需求基线为准

## 1. 目标

把视觉阶段从“生成若干样张或概括性风格说明”升级为受治理的多智能体设计系统。系统必须形成适配阅读优先售前方案的唯一可执行视觉命题、完整 Deck 设计系统和全部页面视觉合同，再由 Presentations 在合同约束下直接完成 2–3 页真实可编辑锚点页的原生视觉设计与实现，并在用户 G3 审阅前完成独立审美、信息表达、编辑阅读、PPT 工程和目标 PowerPoint 实机审查。

## 2. 已确认原则

1. 采用“通用视觉内核 + 阅读优先售前视觉场景能力包”。
2. 固定跨专业设计团队、动态页面专家和独立审查团队共同工作。
3. 生产侧与审查侧的售前视觉专家隔离运行。
4. 多个设计角色先隔离发散，再内部质询收敛，之后跨专业深化和锚点页独立审查。
5. G1/G2 是系统内部质量门，用户不在未收敛方向之间选择。
6. 用户只在 G3 审阅一份完整、连续、可生产的整套视觉合同。
7. Prompt、角色合同、工具任务包、经验切片和返工指令必须版本化。
8. 用户反馈必须先经过反馈治理，视觉生产角色只接收治理后的正式结论。
9. 用户选定的优秀案例对合格方案择优具有较高影响，但不能覆盖最低审美和工程要求。
10. 不保存或展示隐藏思维链，只保存角色、版本、候选引用、结论、证据、失败项和返工指令。
11. 一期正式生产固定采用严格路线 B：多智能体先形成完整视觉合同，Presentations 同时承担原生视觉设计和 PPTX 实现。
12. 原生首版完成全页检查后，Image 2 只可生成背景、纹理、插画、光效等非语义资产，不得决定构图、层级、业务关系或真实证据。
13. 路线 A/C 仅保留为隔离的内部实验路线，不提供给用户选择，也不得把实验整页图传入正式 Presentations 任务。
14. Presentations/开发渲染只作预检；G2 锚点页必须在当前生产平台的 Microsoft PowerPoint 桌面版实机导出并通过四重硬门。

## 3. 固定生产团队

| 中文正式名称 | 主要职责 | 不承担 |
|---|---|---|
| 视觉设计编排智能体 | 编译上下文、调度角色、管理版本、依赖和收敛状态 | 不亲自决定最终审美，不替审查角色放行 |
| 售前视觉策略专家智能体 | 将听众、决策阶段、行业气质、汇报环境和商业目标转成视觉策略 | 不覆盖 G0 内容，不机械套行业模板 |
| 视觉艺术指导智能体 | 建立视觉命题、整体气质、构图语法、页面家族和整套节奏 | 不以单页效果替代整套系统 |
| 编辑设计智能体 | 设计阅读顺序、标题正文关系、长文密度、留白和连续阅读体验 | 不删减或改写冻结内容 |
| 信息设计智能体 | 设计层级、分组、比较、关系、流程、图表和信息表达机制 | 不用装饰图形伪装信息结构 |
| 图像艺术指导智能体 | 规定摄影、截图、插画、图像叙事、裁切、真实性和素材替代策略 | 不生成无来源事实，不让图片承担不可验证结论 |
| PPT 工程智能体 | 在视觉合同约束下用 Presentations 完成原生视觉设计与 PPTX 实现，判断原生对象、受控位图、字体、网格、裁切、可编辑性和目标软件可行性 | 不以工程便利降低设计目标，不翻译 Image 2 整页母版 |

以上是任务级角色，不要求对应常驻进程。

## 4. 动态页面专家

视觉设计编排智能体根据页面家族、内容风险和工具需求动态路由：

- 案例页设计专家智能体；
- 架构图设计专家智能体；
- 数据可视化专家智能体；
- 复杂流程设计专家智能体；
- 其他经场景注册表批准的专业角色。

动态专家必须有独立角色合同、输入范围、输出 Schema 和停止条件。没有对应页面需求时不得运行，避免固定角色膨胀。

## 5. 独立审查团队

| 中文正式名称 | 审查职责 | 隔离要求 |
|---|---|---|
| 售前视觉适配审查智能体 | 检查视觉是否适配听众、决策场景、行业与商业目标 | 不读取生产侧售前视觉专家的自我评价 |
| 独立审美审查智能体 | 检查整体气质、构图质量、节奏、层级、视觉锚点和反模板化结果 | 不直接改稿，只输出证据和返工指令 |
| 信息表达审查智能体 | 检查关系、比较、数据、流程和信息层级是否准确清晰 | 不用“好看”补偿表达错误 |
| 编辑阅读审查智能体 | 检查阅读路径、密度、长文、标题正文、跨页连续性和会后阅读体验 | 不删除冻结内容解决密度问题 |
| PPT 工程审查智能体 | 检查原生可编辑、字体、裁切、对齐、渲染、介质路由和替代机制 | 不以文件可打开代替设计意图成立 |

生产角色不得自我声明通过。各审查角色默认独立运行，由视觉设计编排智能体聚合失败范围并生成返工任务，但不能用多数票放行。

## 6. 视觉提示词架构

```text
稳定视觉治理
+ 售前视觉场景能力包
+ 当前项目与 G0 冻结内容
+ 当前中文角色合同
+ 当前任务合同
+ 工具执行合同
+ 角色化经验切片
+ 审查返工要求（按需）
= VisualAgentContextPack
```

### 6.1 稳定视觉治理

规定事实边界、G0 保护、规则级别、角色隔离、输出合同、可编辑性、严格路线 B、Image 2 非语义资产边界、Presentations 原生设计权限、目标软件与平台证据，以及禁止保存隐藏思维链。

### 6.2 售前视觉场景能力包

至少包含：

- 决策者、业务和技术角色的阅读差异；
- 阅读优先售前方案的页面节奏和证据表达；
- 行业与组织审美倾向的判断方法；
- 方案、价值、架构、案例、实施、风险等页面家族的专业要求；
- 常见视觉失败、反例和回归案例；
- 生产侧与审查侧独立角色合同；
- 版本、适用范围和发布记录。

能力包不得强制固定章节、固定版式或固定配色。

### 6.3 当前项目层

只包含 G0 已冻结内容、任务书、听众、品牌、素材、汇报环境、当前项目治理后的偏好和限制。

### 6.4 角色化经验切片

视觉艺术指导、编辑设计、信息设计、图像艺术指导、PPT 工程和独立审查角色分别接收不同经验。候选经验只能作为建议和检查线索；个人经验仍不得覆盖专业质量门。

## 7. 协作流程

```text
隔离发散
→ 内部质询收敛
→ 跨专业深化
→ Presentations 锚点页原生首版
→ 原生首版全页检查
→ 可选 Image 2 非语义资产
→ Presentations 受控资产整合
→ 当前生产平台 PowerPoint 实机导出
→ 锚点页四重独立审查
→ G1/G2 通过
→ 完整视觉合同投影
→ G3 用户确认
```

### 7.1 隔离发散

售前视觉策略、视觉艺术指导、编辑设计、信息设计和图像艺术指导基于同一 G0 内容分别提出外化方案。候选之间不提前互读，防止首个方案锚定全部角色。

### 7.2 内部质询收敛

审查角色对候选的听众适配、整套节奏、信息表达、编辑阅读和工程可行性分别提出失败证据。视觉设计编排智能体形成唯一收敛任务，不向用户展示方向选择。

### 7.3 跨专业深化

通过 G1 的唯一视觉命题被深化为 Deck Design System、页面家族和全部 Slide Visual Contract。动态页面专家只处理对应高风险页面。

### 7.4 锚点页独立审查

PPT 工程智能体用 Codex Presentations 直接完成 2–3 页真实可编辑锚点页的原生视觉设计与首版实现。首版全页检查通过并冻结后，可按需调用 Image 2 生成非语义资产，再由 Presentations 受控加入。独立审美、信息表达、编辑阅读和 PPT 工程审查智能体必须基于开发预检和当前生产平台 PowerPoint 实机导出分别复核业务语义、视觉完成度、排版工程和目标渲染。任一适用硬条件失败即返工。

## 9. 工具 Prompt 任务包

### 9.1 `NativeVisualDesignBrief`

用于正式路线 B 的 Codex Presentations 原生视觉设计与实现，必须包含完整冻结内容、视觉命题、页面家族、构图/层级/关系目标、允许自主实现范围、原生/位图路由、目标 PowerPoint/生产平台、字体与替代策略、禁止项、验收条件和版本。

### 9.2 `VisualExplorationPromptPack`

只用于显式路线 A/C 内部实验，必须包含隔离输入、禁止互读、结果用途和版本。其整页结果不得进入正式路线 B 的 Presentations Context Pack、VisualContract 或 AnchorSlideSet。

### 9.3 `ImageAssetPromptPack`

只在对应原生首版完成全页检查并冻结后使用。必须包含原生首版引用、目标页面、用途、尺寸、主体、构图、裁切安全区、风格、禁止文字/数字/符号/业务关系/真实证据冒充、来源、隐私边界、资产独立替换要求和版本。

### 9.4 `AnchorSlideEngineeringBrief`

用于 Codex Presentations 实现锚点页，必须引用 `NativeVisualDesignBrief`，并包含完整内容、对象关系、原生/位图路由、编辑要求、字体、网格、素材、替代规则、生产平台、目标 PowerPoint 和验收条件。

### 9.5 `VisualRepairInstruction`

用于定向返工，必须包含失败条件、目标对象、保持不变项、期望结果、上一有效版本和复验角色。

工具任务包只执行已经形成的专业意图，不得自行扩大内容或改变 G0 事实。

## 10. 质量合同

### 10.1 必须严格遵守

- 不改变 G0 冻结内容、事实身份、来源和方案边界；
- 每页核心主张和阅读顺序可识别；
- 事实文字、数字、图表、表格和关键关系保持原生可编辑；
- 不用整页位图伪装可编辑；
- 图片、截图和案例素材的使用目的与来源清楚；
- 不产生溢出、裁切、遮挡、字体缺失和错误关系。
- 正式路线不读取或复刻 Image 2 整页实验结果；Image 2 资产移除后页面业务语义和结构仍完整；
- G2 锚点页具有当前生产平台 PowerPoint 实机导出证据，导出前后 PPTX 哈希一致；

### 10.2 最低审美要求

- 视觉命题适配听众、场景和内容；
- 整套具有统一但不机械重复的构图语法；
- 页面之间有清晰节奏和页面家族变化；
- 信息层级、分区、对齐、留白和视觉锚点有效；
- 图片、图示、数据和文字共同支持核心主张；
- 长文和复杂内容适合会后独立阅读；
- 不出现卡片墙、截图堆叠、无语义装饰、低对比和 AI 模板感。
- 目标 PowerPoint 实机输出中的构图、层级、留白、视觉锚点和页面家族表现不低于已通过的开发预检。

### 10.3 参考实现

- 具体网格、分隔线、背景、字体组合和图片风格；
- 某类页面的常见布局；
- 用户优选案例中的具体实现。

参考实现允许被更优秀方案替代。分隔线等元素不得被全局禁止；只在承担结构分区、对齐轴或阅读引导时使用，避免无语义装饰、重复分隔、高对比粗线和孤立线段。

## 11. 反馈治理

用户对视觉合同、锚点页或成稿的意见先进入反馈治理流程：

```text
原始反馈
→ 专业诊断与反例检查
→ FeedbackGovernanceRecord
→ VisualChangeSet
→ 定向返工
→ 原审查角色复验
→ 用户结果评价
```

视觉生产和审查角色不直接把用户原话提升为跨页面规则。用户在了解专业建议后仍坚持的决定，只作为当前项目约束执行，除非后续独立进入经验验证链。

## 12. 用户介入与自动返工

G1/G2 失败默认自动返工。只有以下情况暂停：

- G0 内容或业务语义存在歧义；
- 关键素材缺失；
- 用户反馈与最低审美、已确认品牌或工程边界发生高影响冲突；
- 可编辑性与设计意图无法自动裁决；
- 系统在待验证限制内无法收敛。

用户只看到当前阶段、失败范围、已修复内容、必要证据和是否需要判断，不看内部对话或候选争论。

## 13. 经验进化

1. 用户优选案例对视觉艺术指导、编辑设计、信息设计和图像艺术指导角色的择优影响较高。
2. 用户否决稿、审查失败稿和工程掉级记录优先进入独立审查和返工角色经验切片。
3. 经验必须保存来源、版本、机制、适用范围、反例和结果。
4. 项目反馈只在治理后影响当前项目；跨项目经验必须另行验证。
5. 稳定视觉场景能力包只通过版本发布更新，不由运行时自动改写。

## 14. 验收标准

1. 固定生产、动态专家和独立审查三类角色边界清楚，正式名称全部为中文。
2. 生产侧和审查侧售前视觉专家上下文隔离。
3. 视觉阶段按隔离发散、内部质询、跨专业深化、Presentations 原生首版、可选非语义资产增强和目标 PowerPoint 实机审查运行。
4. G1/G2 不要求用户选择方向或逐页确认。
5. Deck Design System、全部页面合同和 2–3 页严格路线 B 锚点页均存在并通过适用硬条件。
6. Prompt、角色合同、工具任务包、经验切片和返工指令均有版本。
7. 正式路线中 Image 2 只在原生首版后生成非语义资产；Codex Presentations 是唯一 PPTX 创建、原生视觉设计、编辑和预检路线。
8. 用户反馈先治理再生成 `VisualChangeSet`，局部反馈不会自动扩大为全局规则。
9. 用户优选案例只在通过专业资格门的候选中影响择优。
10. 全过程不保存或展示隐藏思维链。
11. 路线 A/C 只在显式实验中运行，输入、Context Pack、产物和审查与正式路线 B 隔离，用户不需要选择路线。
12. G2 锚点页保存当前生产平台 PowerPoint 实机导出的操作系统、PowerPoint 版本、字体、PPTX 哈希、PDF/逐页图片和四门结论。
13. 业务语义、视觉完成度、排版工程和目标软件渲染任一失败即保留上一有效版本、定向返工并重新复验；智能体轮次更多不构成放行依据。
14. 默认不要求同一项目同时验证 Mac 和 Windows；明确跨平台目标时增加目标平台复验，WPS 无独立证据不声明兼容。
