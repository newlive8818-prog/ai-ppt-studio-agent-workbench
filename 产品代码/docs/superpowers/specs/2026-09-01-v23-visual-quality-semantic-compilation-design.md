## 1. 文档身份与事实边界

本文定义 AI PPT Studio v2.3“视觉质量与设计感攻关”的研发前设计。它不修改 v2.2 冻结结论，也不把实验目标写成当前能力。

本文必须始终区分五类状态：

1. `机制实现`：相应对象、约束或流程已经进入 v2.3 代码；
2. `自动化验证`：测试、构建、渲染、结构、布局或规则检查通过；
3. `真实 PPT 样本验证`：机制已经在批准的代表性样本上实际运行并留下前后证据；
4. `目标 PowerPoint 检查`：相同 PPTX 已在当前发布策略要求的 Microsoft PowerPoint 环境中检查显示、编辑、字体与兼容性；
5. `用户视觉认可`：用户看过实际结果并明确认可视觉方向或质量。

任一层级不得自动推断下一层级。尤其禁止把代码完成、测试通过、渲染成功、无溢出、无控制台错误或自动规则通过表述为“视觉质量已验收”或“产品已可交付”。

v2.2 已基本建立视觉治理对象、Gate、ReviewSession、原生可编辑路线、发布目标和经验数据面，但尚未证明这些机制能稳定提升页面的设计判断和真实交付质量。当前主要风险不是“缺少更多模板”，而是页面语义没有形成可执行的视觉推理链，视觉合同与 Codex Presentations 原生实现之间可能发生设计意图丢失，自动化检查也无法代替审美审查与用户认可。

### 1.3 待验证假设

- 把页面主张、读者判断和主信息关系编译为不同视觉机制，可以减少固定卡片、节点、流程轨道和中心圆的重复使用；
- 为 Slide Visual Contract 增加少量高价值、闭合语义，而不是无限增加描述字段，可以改善 handoff；
- 以真实样本前后对比、五秒测试、反模式审查和目标 PowerPoint 检查共同约束生成，能比单纯提示词或模板选择更稳定；
- 现有 `same-type | global` 经验数据面能够承载视觉机制和反模式，不需要建立第三套经验库；
- Codex Presentations 能在不牺牲原生可编辑性的前提下实现首轮两类页面机制。

这些假设只有通过首轮样本实验后才能保留、收窄或否决。

## 2. 要解决的问题

v2.3 面向阅读优先的售前解决方案汇报，专门处理以下结果问题：

- 页面有明显 AI 味和组件库感；
- 不同内容被套入相似卡片、节点、圆形和流程结构；
- 页面看似整齐，却没有清晰视觉重心和阅读张力；
- 图片与页面主张无关或仅作氛围装饰；
- 文字被换成形状，但信息关系没有被视觉化；
- 图表或关系图结构正确，却没有明确观点；
- 跨页构图、密度和节奏变化不足；
- 自动化检查通过，但真实阅读和 PowerPoint 使用体验仍不足；
- 设计经验无法以可追溯、可评估、可回滚方式影响下一页或下一项目。

v2.3 不把问题简化为换模板、增加素材、调整颜色、增加装饰或让模型自由发挥。

## 3. 设计目标与非目标

### 3.1 目标

1. 建立从内容语义到页面视觉机制、再到原生 PPTX 的可追溯编译链；
2. 让每页的构图选择由页面任务和主信息关系驱动，而不是由内容类型直接匹配固定模板；
3. 让 Visual Brief、Deck Design System 和 Slide Visual Contract 各自承担清晰且不重复的职责；
4. 把 AI 味和低设计感反模式转为可检查、可举证、可回写的审查对象；
5. 用真实样本前后对比证明机制是否有效，再决定是否扩展到全量页面；
6. 保持 Codex Presentations 为唯一 PPTX 读写、创建、编辑、渲染和检查路径；
7. 保持语义文字、数据、表格、图表、简单关系图和连接器原生可编辑；
8. 把目标 PowerPoint 检查和用户视觉认可保留为不可替代的后置证据。

### 3.2 非目标

- 不重做 v2.2 Mission、内容生产、G0、ReviewSession、G3/G4 或发布治理链；
- 不推进现有 v2.2 Runtime 验收项目的 G3/G4；
- 不建设通用 PPT 模板市场、素材市场或独立 Web 产品；
- 不新增第二个 PPTX 编译器，不使用 `python-pptx`；
- 不把 Image 2 整页图或含事实文字的位图作为最终幻灯片；
- 不以单一自动审美分数替代二元规则、人工审查和用户认可；
- 不在首轮重做完整 27 页；
- 不把两份分享型 PPTX 当作真实售前正式验收样本；
- 不自动修改四份 v2.2 权威基线；任何产品合同变更必须在设计获批后另行形成受影响基线清单并获得批准。

## 4. 六类缺口与根因

### 4.1 产品机制缺口

现有对象已经要求 Visual Brief、Deck Design System 和全页 Slide Visual Contract，但正式合同主要验证字段存在、版本一致、严格路线 B、可编辑性和 Gate 证据。尚未证明系统会强制形成“页面主张—读者判断—信息关系—视觉机制”的设计推理，也没有形成样本实验的正式证据闭环。

### 4.2 设计知识缺口

现有字段能描述构图、层级、字体、颜色、图像、图表和可编辑性，但缺少一套围绕页面任务进行选择的可执行知识：什么时候使用比较、路径、层级、因果、边界、系统、循环或张力构图；什么时候必须放弃节点图、卡片或背景图；图片应承担什么叙事任务；相邻页面为什么需要不同密度和节奏。

### 4.3 页面生成策略缺口

当前风险是“内容类型 → 页面家族/常见组件 → PPTX”，而不是“主信息关系 → 视觉机制 → 对象编排”。这种路径容易让不同内容收敛为同一套模板语法。v2.3 的核心是替换选择依据，不是扩充模板数量。

### 4.4 审美审查缺口

现有自动化更适合检查溢出、遮挡、字体、对象、连接器、裁切、哈希和目标渲染。低廉感、模板感、弱焦点、无意义装饰、图片无叙事任务、构图同质化和跨页节奏单一需要新的反模式审查，但这些审查不能伪装成完全客观的万能评分。

### 4.5 原生 PowerPoint 实现缺口

Presentations handoff 已要求完整合同和原生对象，但可能仍缺少从“视觉机制”到“对象角色、空间约束、连接语义、层级顺序、图片裁切、可替换边界”的闭合映射。实现者可能得到很多描述，却不知道哪些设计关系不可丢失。

### 4.6 真实用户验收缺口

现有测试和渲染证据不能证明真实售前可用。正式扩展前必须引入 3 至 5 个代表性真实售前样本、目标 PowerPoint 环境检查和用户视觉认可，并保留每次修订记录。

## 5. 总体方案

采用一条主线和两个约束层：

```text
路线 A：最小合同补强
       ↓
路线 C：视觉语义编译主线
       ↓
Codex Presentations 原生实现
       ↓
路线 B：样本审查、反模式与经验回写
```

这不是三个并行重构项目。首轮只建立一个垂直切片：从两个批准页面的原始内容出发，形成视觉合同、语义编译计划、原生 PPTX、自动证据、人工审查和用户判断。

## 6. 视觉语义编译模型

### 6.1 单页编译链

每页采用以下顺序：

```text
页面主张
→ 读者五秒内应形成的判断
→ 主信息关系
→ 视觉机制
→ 视觉重心
→ 证据/图像角色
→ 文字层级
→ 构图与阅读顺序
→ 与前后页的节奏关系
→ 原生对象与位图路由
→ PowerPoint 实现约束
→ 验收与反模式检查
```

任何一步都不得从现成模板名称开始。页面家族只能作为检索和经验匹配维度，不直接决定最终构图。

### 6.2 主信息关系

首轮支持以下关系词汇，但不把它们固定为模板：

- `comparison`：对比、替代、前后变化；
- `sequence`：步骤、阶段、时间、交付路径；
- `causality`：原因、机制、结果；
- `hierarchy`：层级、归属、治理关系；
- `network`：多主体协作、依赖、交互；
- `system-boundary`：系统内外、角色边界、责任切分；
- `cycle`：反馈、学习、迭代闭环；
- `tension`：矛盾、风险、取舍、冲突；
- `evidence-to-judgment`：材料、证据、判断与行动；
- `single-focus`：一个结论或一个关键对象。

每页必须选一个主关系，可有一个辅助关系。若同时选择过多关系，视为合同不收敛。

### 6.3 视觉机制

视觉机制是实现主信息关系的构图方法，不是模板文件。首轮候选包括：

- 方向性流动与汇聚；
- 对照空间与角色切分；
- 中心对象和约束边界；
- 路径、阶段和门；
- 证据锚点与判断焦点；
- 比例、距离、规模或密度对比；
- 一张具有叙事任务的主图与少量原生标注；
- 原生关系图，但节点形状、连接语义和层级必须服务主张。

同一视觉机制可跨页复用，但必须说明适用条件和变化理由；不能因为是同一 Deck 就让所有页面使用同一构图。

### 6.4 图像角色

每张图像必须声明一个主角色：

- `evidence`：真实材料或可核验事实证据；
- `structure`：帮助理解空间、系统或关系结构；
- `explanation`：解释难以用文字或简单形状表达的机制；
- `emotion-context`：建立场景、情绪或商业语境。

若删除图像后页面理解完全不变，默认判定为可能的装饰性资产，除非合同明确说明其节奏或语境价值。Image 2 在定版前可承担整页设计，候选图中的内容须在定版前核对。定版后其设计与绑定文案约束转换；最终 PPTX 的主要文字、数字和关键关系仍须原生，复杂无字装饰可独立替换，不能用生成内容冒充真实证据。

### 6.5 跨页节奏

Deck Design System 不只定义颜色、字体和网格，还必须定义：

- 章节开合；
- 高密度与低密度页面的交替；
- 图像主导、结构主导、数据主导和文字主导页面的比例；
- 连续两页是否允许相同构图轮廓；
- 视觉停顿页、转折页和证据页的节奏职责；
- 视觉重心的移动方式；
- 强调色的节制规则。

跨页变化不是为了随机多样，而是为了服务叙事阶段和阅读负担。

### 6.6 非强制设计哲学参考

以下内容是用户提供的设计哲学参考，用于扩展设计师的观察视角和方案可能性，不新增强制页面模板、固定字体大小、必选电影镜头、二元 Gate 或自动失败规则。设计师可以采用、组合、调整或不采用；是否有效仍以具体页面目标、实际样本、目标 PowerPoint 结果和用户判断为准。

#### 阅读顺序不是文字排序

阅读顺序可被理解为读者注意力在页面中的运动路径。除标题、字号和编号外，可以通过空间位置、比例、方向、重叠、留白、前后景、颜色和对象关系安排注意力。现有合同对 `reading_order` 的要求继续有效；本哲学不强制某一种路径，也不要求每页都使用箭头或编号显示路径。

#### 目录和章节标题承担结构聚焦

目录、章节标题和章节切换页可以承担“建立全局地图、提示当前位置、声明叙事转折和重新聚焦”的任务。把目录或章节标题机械缩小为页眉式装饰，可能削弱逻辑焦点和读者的结构化理解；但本哲学不规定统一字号、不要求每套 PPT 必须有传统目录页，也不要求章节页采用固定版式。设计时应先判断它在当前叙事中的结构任务，再决定其视觉权重。

#### 借鉴电影或拍摄者视角

设计师可以借鉴导演、摄影师或剪辑者的观察方式，思考：读者站在什么视角、画面主体是谁、背景提供什么语境、哪些对象进入或退出注意力、需要全景还是局部、需要建立空间还是推进动作、相邻页面如何转场。该视角只用于帮助安排对象、景深感、焦点和叙事节奏，不要求模仿电影画幅、分镜模板、镜头术语或影视风格。

#### 证据与观点形成可读逻辑

设计师可以把证据、解释和观点理解为不同角色：证据回答“依据是什么”，解释回答“这些依据意味着什么”，观点回答“读者应形成什么判断”。三者的关系可以通过位置、方向、层级、对照、因果、聚合或阶段推进表达，不要求每页都画成显式流程图。事实身份和来源追溯仍遵守既有硬约束；本哲学不把某一种证据—观点构图设为强制模板。

#### 每页同时思考目标、布局与构图

设计者可同时追问：本页要完成什么叙事目标，内容需要怎样的空间布局，什么构图最能强化目标。`目标` 不是标题复述，`布局` 不是组件排列，`构图` 也不是装饰风格。三者可共同影响视觉重心、对象比例、阅读路径和留白，但不要求在用户界面中增加一套固定问卷或逐项确认流程。

#### 参考的治理边界

- 这些哲学不能直接写入 `must-follow` 或 `minimum-aesthetic` 规则；
- 未采用某条哲学不能单独导致 G1/G2 失败；
- 目录标题较小、未使用电影化视角或未显式画出证据—观点连接，都不能自动判为反模式；
- 只有在具体样本中出现可观察的问题或改善，并有人工或用户结果证据时，相关机制才可进入 `same-type` 经验；
- 只有满足现有跨类型真实成功条件或用户明确声明全局适用后，才可进入 `global`；
- 任何被经验化的内容都必须保留适用范围、反例和回滚能力。

## 7. 对现有视觉对象的最小补强

首轮优先扩展现有对象，不平行创建第二套视觉真相。以下字段名和语义是设计合同；实施计划只能确定代码落点、迁移顺序和兼容实现，不能重新定义字段含义。

### 7.1 Visual Brief

Visual Brief 必须覆盖：

- 受众及阅读/演示场景；
- 决策任务；
- 设计立场与情绪边界；
- 品牌边界；
- 内容密度策略；
- 跨页节奏；
- 图像总体语言；
- 图表和关系图总体语言；
- 目标 PowerPoint 与字体约束；
- 全 Deck 禁止模式；
- 五秒判断测试的总体口径。

继续使用现有 `design_proposition`、`audience_fit`、`narrative_rhythm`、`imagery_strategy`、`diagram_strategy` 和 `powerpoint_constraints`。首轮最小新增结构化字段为：

- `decision_task`；
- `design_stance`；
- `emotional_boundary`；
- `brand_boundary`；
- `density_strategy`；
- `forbidden_patterns`；
- `five_second_test_contract`。

不得为字段完整而增加与首轮生成或验收无关的描述项。

Visual Brief 可以包含可选的 `design_philosophy_refs`，用于登记本项目希望参考的哲学及其来源。该字段缺失或某条参考未被采用都不得导致合同失败；它不能替代 `forbidden_patterns`、`rule_definitions` 或正式验收条件。

### 7.2 Deck Design System

Deck Design System 必须覆盖：

- 主题命题；
- 构图语法而非固定模板；
- 栅格、间距和对齐原则；
- 字体与字号层级；
- 颜色与强调色预算；
- 图像、图表、表格和关系图语言；
- 页面家族及其适用条件；
- 跨页密度和节奏；
- 原生/位图路由；
- 可编辑规则和降级规则；
- 反模式清单；
- 二元验收规则与证据方法。

现有 `forbidden_patterns` 和 `rule_definitions` 继续作为权威入口，不新增平行审美规则仓库。首轮最小新增结构化字段为：

- `density_rhythm`；
- `cross_slide_rhythm_rules`；
- `emphasis_budget`；
- `image_language`；
- `diagram_language`；
- `five_second_test_rules`。

### 7.3 Slide Visual Contract

每页在现有冻结内容与设计字段之外，必须明确：

- 页面主张；
- 五秒读者判断；
- 主信息关系与辅助关系；
- 视觉机制；
- 视觉重心；

- 禁止出现的模板化表达；

- 文字密度上限或删减策略；
- 原生对象类型、连接语义和层级要求；
- 目标 PowerPoint 中不可丢失的实现约束；
- 自动检查、人工审查和用户判断分别需要什么证据。

对应的首轮最小新增字段为：

- `reader_judgment`；
- `primary_relationship`；
- `secondary_relationship`，允许为空但字段必须存在；
- `visual_mechanism`；
- `focal_point`；
- `asset_roles`；

- `next_rhythm_relation`；
- `text_density_budget`；
- `powerpoint_implementation_requirements`；
- `acceptance_evidence_plan`。

不得重复或改写 G0 已冻结的内容事实；新增信息只描述视觉解释、实现和验收。

Slide Visual Contract 可以在 `visual_mechanism`、`focal_point`、现有 `reading_order` 和节奏关系中说明采用了哪些哲学启发，但不新增强制的电影镜头分类、目录字号或证据—观点固定图式。

## 8. Visual Compilation Plan

为了避免把 Slide Visual Contract 直接翻译成任意 PPTX，在合同和 Presentations handoff 之间引入一个受控的 `VisualCompilationPlan` 不可变派生 artifact，artifact kind 为 `visual-compilation-plan`，当前 head 为 `visual/compilation-plan`。

### 8.1 身份

`VisualCompilationPlan` 是针对一个当前视觉版本的确定性实现计划，不是新的内容真相，也不是用户表面。它只能由当前三层视觉合同及其绑定输入生成；任何上游 ref、sourceVersion 或 revision 改变都使旧计划过期。它绑定：

- 当前 ReadingDeckBlueprint ref；
- 当前 Visual Brief ref；
- 当前 Deck Design System ref；
- 当前 Slide Visual Contract ref；
- 当前 sourceVersion、revision 和 ReleaseTargetPolicy ref；
- 生成它的角色任务和适用经验版本；
- 目标 Codex Presentations handoff 版本。

### 8.2 每页最小内容

- `slide_id`；
- `primary_relationship`；
- `visual_mechanism`；
- `focal_point`；
- `reading_path`；
- `object_plan`：对象角色、类型、层级和编辑性；
- `connector_semantics`：连接方向、含义和禁止穿越；
- `asset_plan`：来源、角色、裁切、替换边界；
- `layout_constraints`：边距、区域、对齐和密度；
- `native_bitmap_routing`；
- `powerpoint_constraints`；
- `anti_pattern_checks`；
- `acceptance_evidence_plan`。

### 8.3 边界

- 它不能修改冻结文案、事实、数据、来源或演讲备注；
- 它不能引入与 Slide Visual Contract 冲突的第二套设计结论；
- 它只把已确认视觉语义转换为可执行对象计划；
- 它必须可由当前合同确定性重新生成并比较差异；
- 同一组输入与同一编译器版本必须生成相同的规范化 payload 和 artifact ref；
- Codex Presentations 只能消费与当前三层视觉合同 refs、sourceVersion、revision 和 ReleaseTargetPolicy ref 完全一致的当前计划；
- 它不能自行通过 G1、G2、G3 或 G4；
- 若后续真实样本证明独立 artifact 没有带来可追溯性、可验证性或 handoff 稳定性收益，必须另开设计变更将其退化为正式投影；首轮实施不得同时保留 artifact 与第二套非权威投影语义。

## 9. Codex Presentations handoff

handoff 必须包含：

- 当前 ReadingDeckBlueprint；
- Visual Brief；
- Deck Design System；
- 全部或首轮目标页的 Slide Visual Contract；
- Visual Compilation Plan 或等价正式投影；
- 真实本地资产及来源；
- 输出 PPTX、渲染和证据路径；
- 当前 ReleaseTargetPolicy；
- 精确修改范围、expectedRevision 和授权 Gate；
- 不可丢失的语义关系和对象编辑性要求；
- 反模式检查清单；
- 前后版本对比要求。

原生实现规则：

- 标题、正文、标签、事实、数字、表格、图表、简单关系图、连接器、业务关系、Logo 和页码保持原生；
- 图片、截图、复杂插画、纹理和氛围背景作为独立可替换图片层；
- 连接器必须有语义，不得仅为装饰；
- 图像裁切必须服务构图和焦点；
- 不允许整页位图、烘焙事实文字或无法追溯的数据；
- 若设计意图无法在目标 PowerPoint 中稳定实现，必须记录降级策略，而不是静默换成模板页。

## 10. AI 味与低设计感反模式

首轮建立以下反模式目录，每项必须包含触发条件、观察证据、允许例外和修复方向：

1. 每页都是标题、卡片、图标和说明文字；
2. 所有内容平均分配，没有明确视觉重点；
3. 为填满页面添加装饰线、渐变、发光或无意义图标；
4. 使用与页面主张无关的背景图片；
5. 一页包含过多相似卡片；
6. 文字只被换成形状，没有转化为视觉关系；
7. 所有页面使用同一种构图；
8. 信息层级只依赖字号，缺少空间、位置、比例和构图层级；
9. 色彩过多或强调色滥用；
10. 图片只有装饰任务，没有证据、结构、解释或语境职责；
11. 图表数据正确但没有明确观点；
12. 页面整齐但没有视觉张力或阅读焦点；
13. 跨页缺少密度、节奏和轮廓变化；
14. 自动化验证通过但真实阅读体验差；
15. 为追求科技感而使用泛蓝紫、发光、网格、粒子和玻璃效果；
16. 关系图节点和连线数量很多，但连接语义不清；
17. 中心圆、放射线、流程轨道或四象限被无条件复用；
18. 图片和原生对象互相争夺焦点；
19. 主张在标题里，但页面主体没有提供视觉证据或关系；
20. 页面变化来自装饰替换，而不是信息关系和构图变化。

审美审查不能仅输出总分。每个失败必须指向具体反模式、页面区域、证据和建议修复机制。

## 11. 首轮两页实验

### 11.1 样本身份

机制试验源文件：`当 AI 开始负责交付.pptx`。该文件只读，不纳入 v2.3 Worktree，不修改原文件。

首轮目标页：

- 第 5 页：`AI 改变的不是按钮，而是产品的执行主体`；
- 第 8 页：`把 AI 的设计知识固化进工程`。

### 11.2 第 5 页实验任务

验证图像主导的复杂关系页：

- 页面主张：AI 原生产品改变了主要执行责任的分配；
- 五秒判断：读者首先看到执行主体从人转向 AI，软件承担治理和事实边界；
- 主信息关系：`system-boundary + network`；
- 图像任务：承担结构或解释，不只是科技氛围；
- 视觉重心：主要执行者变化；
- 原生对象：人、AI、软件、责任说明、判断结论和必要连接关系；
- 禁止模式：与主张无关的抽象背景、三张平均卡片、标签贴在背景上但没有关系、装饰性粒子和无语义连线。

### 11.3 第 8 页实验任务

验证原生结构主导的流程/架构页：

- 页面主张：AI 的设计能力必须通过受治理的视觉合同和原生实现链进入工程；
- 五秒判断：读者首先看到设计知识从输入到合同、实现和 Gate 的受控转化路径；
- 主信息关系：`sequence + evidence-to-judgment`；
- 视觉重心：从视觉策略到原生交付的关键转化段；
- 原生对象：阶段、门、输入输出、连接器、版本或证据标识；
- 禁止模式：等距节点流水账、所有步骤同权、连接线无方向、用颜色代替阶段语义、仅把英文术语摆成流程。

### 11.4 对照要求

两页必须使用不同且合理的视觉机制。第 5 页不能退化为第 8 页式节点流程；第 8 页不能依赖一张大图掩盖工程关系。对照必须保留原始页、视觉合同、编译计划、生成页、原生 PPTX、渲染、审查、用户反馈和修订记录。

## 12. 样本证据包

每个样本页面建立一个不可混淆的证据包：

- 原始 PPTX ref、文件哈希、页码和渲染图；
- 原始内容与页面主张；
- Visual Brief ref；
- Deck Design System ref；
- Slide Visual Contract ref；
- Visual Compilation Plan ref 或正式 handoff 投影；
- 生成 PPTX ref、PPTX 哈希和页码；
- 自动化验证结果；
- 人工视觉审查结果；
- 目标 PowerPoint 证据；
- 用户反馈或视觉认可；
- 修订前后 refs；
- 提炼出的 same-type 机制、反模式或不入库理由。

机制样本和正式售前验收样本必须用不同身份。机制样本成功只证明首轮机制可继续验证，不证明正式场景通过。

## 13. 五秒测试与人工视觉审查

### 13.1 五秒测试

向审查者展示单页五秒后隐藏，记录：

- 首先注意到的对象；
- 认为页面在表达什么；
- 认为对象之间是什么关系；
- 是否能指出下一步阅读路径；
- 是否出现被装饰、背景或次要信息误导的情况。

通过条件不是逐字复述标题，而是形成与合同一致的核心判断。首轮由用户或明确指定的人工审查者执行，AI 自评不能替代。

### 13.2 人工审查维度

- 主张是否通过页面主体而非只靠标题成立；
- 视觉重心是否唯一且清楚；
- 主信息关系是否可读；
- 图片或关系图是否有不可替代的叙事任务；
- 文字密度和层级是否支持阅读；
- 是否命中反模式；
- 与前后页的节奏是否合理；
- 页面是否看起来像真实售前交付而非组件演示；
- 原生对象和编辑方式是否符合正常 PowerPoint 使用习惯。

人工审查可以给出辅助评分，但放行必须基于二元条件和具体证据，不使用总分抵消硬失败。

### 13.3 非强制哲学提问

人工审查可以按页面需要选用以下问题，但不得把它们全部变成机械检查表：

- 读者的注意力从哪里进入，按什么顺序移动，在哪里停留；
- 如果存在目录、章节标题或转场页，它是否真正帮助读者建立结构和当前位置；
- 当前页面的观察视角、主体、背景、前后景和转场是否强化了叙事目标；
- 证据、解释和观点之间的逻辑是否能从页面主体中被读出；
- 页面目标、布局安排和构图选择是否互相支持。

这些问题产生的是观察和讨论线索。只有当问题被具体页面证据证实并命中已批准的验收条件或反模式时，才形成失败结论。

## 14. 自动化检查边界

自动化可以检查：

- 合同和 lineage 完整性；
- 冻结内容未被视觉阶段改写；
- 页面主关系和视觉机制存在且收敛；
- 必需原生对象和连接语义被声明；
- 禁止整页位图和语义信息位图化；
- 文件哈希、目标环境和证据绑定；
- 画布溢出、遮挡、裁切、换行、字体、连接器和对象结构；
- 连续页面的构图机制重复警告；
- 图片角色和来源是否登记；
- 反模式规则中可程序化的部分。

自动化不能单独判定：

- 页面是否高级、廉价或有设计感；
- 五秒判断是否正确；
- 图片是否真正具有叙事力量；
- 页面是否适合真实客户售前；
- 用户是否认可；
- 一个视觉经验是否应晋级为 global。

## 15. 视觉经验回写

首轮复用现有 `same-type | global` 两层经验，不新增第三层。

可回写内容：

- 已被用户认可并有前后证据的视觉机制；
- 明确失败的反模式；
- 图像角色、构图、密度、字体、颜色、图表、连接器或 PowerPoint 实现经验；
- 适用范围、反例和失败条件；
- 对应的真实样本、渲染和用户结果 refs。

禁止回写：

- 客户名称、客户事实、数字、文件、Logo、完整页面或未授权素材；
- 两份分享型样本的完整设计；
- 自动化通过但无用户认可的“成功经验”；
- Gate 绕过或权限规则；
- 仅因个人喜欢而被表述为全局规则的偏好。

首轮机制默认只能进入 `same-type` 候选。只有用户明确声明全局适用，或后续至少两个不同 type signature 的真实接受证据满足现有规则，才讨论进入 `global`。

本节 6.6 的非强制设计哲学默认不进入经验库。只有某条哲学在具体页面中被转化为可描述的机制、产生可观察的前后差异，并获得用户结果证据后，才按上述规则评估是否吸收；不得把“像电影”“章节标题要大”或“证据和观点要清楚”这类抽象表述直接存成通用规则。

## 16. Gate 与状态边界

v2.3 首轮采用独立实验身份，不复用或推进 v2.2 Runtime 项目的 Gate。

- G0：不重做；首轮使用批准机制样本中冻结的页面内容进行实验，不把其视为真实售前 G0；
- G1：可用于内部合同和编译计划检查，但只证明实验视觉方案达到内部可实现状态；
- G2：只有相同 anchor PPTX 的语义、审美、工程、编辑性和当前必需目标证据都成立时才可记录；
- G3：仍需用户对当前实验视觉版本明确判断；保存反馈、测试通过或渲染成功均不等于 G3；
- G4：首轮机制实验不进入正式交付 G4；正式 G4 留给后续独立 Runtime 真实售前验证项目。

## 17. 分阶段验证与退出条件

### Phase V0：合同可执行性

目标：两页都形成闭合的 Visual Brief、Deck Design System、Slide Visual Contract 和编译计划。

退出条件：

- 五秒判断、主信息关系、视觉机制、重心、图像角色、原生对象、反模式和证据计划均明确；
- 两页视觉机制不同且与页面任务匹配；
- 没有改写冻结内容；
- 没有第二套业务真相。

失败处理：收窄或修改对象语义，不进入 PPTX 实现。

### Phase V1：原生 anchor 实现

目标：使用 Codex Presentations 生成只包含两页的原生可编辑实验 PPTX。

退出条件：

- 语义文字、关系和连接器原生可编辑；
- 图片是独立可替换层；
- 无整页位图和烘焙事实文字；
- 自动化结构、布局和渲染检查通过；
- 原始内容与实现一致。

失败处理：修复 handoff 或实现约束，不扩展页面。

### Phase V2：人工和目标环境检查

目标：对两页做五秒测试、反模式审查和目标 macOS Microsoft PowerPoint 检查。

退出条件：

- 五秒判断与合同一致；
- 没有未处理的首要反模式；
- 字体、裁切、连接器、编辑和布局在目标 PowerPoint 中成立；
- 每个结论都有页面或环境证据。

失败处理：保留失败版本，定向修订，再次检查。

### Phase V3：用户判断和经验回写

目标：用户看到实际页面并明确接受、拒绝或要求修改，系统形成有边界的 same-type 经验。

退出条件：

- 用户结果与当前 PPTX 哈希、页面和版本绑定；
- 成功机制和失败反模式有适用范围和反例；
- 没有把实验结论写成 v2.2 已验收事实；
- 用户未认可时不得扩展至正式样本。

### Phase V4：正式样本扩展决策

只有 V0—V3 全部满足后，才提出下一份设计或实施计划，选择 3 至 5 个真实售前样本，至少覆盖：

- 事实与数据；
- 复杂关系或架构；
- 流程与路线图；
- 方案价值与结论；
- 图片或视觉隐喻。

首轮机制样本通过不自动授权 V4。

## 20. 风险与控制

### 20.1 过度建模

风险：新增大量字段和 artifact，却没有改善输出。

控制：首轮只保留能改变第 5、8 页生成或审查的语义；V0 失败即停止实现。

### 20.2 新模板化

风险：把视觉机制词汇固化成另一套模板库。

控制：机制绑定信息关系和适用条件；两页必须选择不同机制；经验记录反例。

### 20.3 审美伪客观化

风险：用自动评分掩盖真实阅读问题。

控制：自动化只做可证检查；五秒测试、人工审查和用户认可分开记录。

### 20.4 样本过拟合

风险：两份分享型样本被误当通用售前标准。

控制：它们只作为机制实验；正式扩展必须使用 3 至 5 个真实售前样本。

### 20.5 可编辑性退化

风险：为了视觉效果把语义对象烘焙成图片。

控制：Image 2 定版设计与内容忠实、原生编辑性均为硬约束；复杂无字装饰保留为独立可替换层；逐页还原核验与目标 PowerPoint 检查不可省略，不得因编辑性要求静默重排或改文案。

### 20.6 v2.2 污染

风险：实验修改冻结分支、标签、Runtime 或验收事实。

控制：独立 Worktree、分支、Runtime 项目、计划和证据；不推进 v2.2 G3/G4；不公开发布。

## 21. 设计验收标准

本设计规格本身只有在以下条件满足后才能进入实施计划：

- 用户确认推荐路线和两页首轮范围；
- 用户确认五秒判断是首要门槛、去模板化与视觉张力是第二门槛、原生可编辑和目标 PowerPoint 稳定渲染是不可降低约束；
- 六类缺口、视觉语义编译链、三个现有视觉对象的职责、VisualCompilationPlan 边界、反模式目录、样本证据包、五层验收和阶段退出条件不存在冲突；
- 阅读顺序、目录/章节聚焦、拍摄者视角、证据—观点关系以及目标—布局—构图已作为非强制设计哲学参考登记，不被误写为固定模板或 Gate；
- 实施计划将把 `VisualCompilationPlan` 落为由当前三层视觉合同确定性生成的不可变派生 artifact，不得改为第二套权威设计合同；
- 实施计划将先列出四份权威基线的受影响差异，由用户决定是否、何时更新；
- 用户明确批准本设计规格后，才可编写实施计划；
- 用户明确批准实施计划后，才可编写产品代码。
