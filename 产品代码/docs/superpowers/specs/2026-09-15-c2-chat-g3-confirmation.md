## 用户行为

在当前对话展示三页审核对象和确切视觉合同后，用户可直接回复“接受，达到要求”或明确确认当前视觉合同和 G3。无需额外表单。用户已接受的同一文件不重复生成、重复评价。G4 和整套交付属于 C3，G4 open 不是 C3 启动授权。

“明确”指结合紧邻的唯一 G3 审核说明，可以确定用户接受了该对象，不强制用户在回复中输入 Gate 名称。单独的“接受/达到要求”仅在完整快照、确切合同、revision 和前置 G3 说明全部匹配时有效；脱离该上下文无效。这保留用户实际使用的自然对话形式。

## 实现合同

- 本地 G3 adapter 读取 Codex Desktop 保存的原始会话日志。引用包含 thread ID 与 message ID；只检查对应的唯一非继承任务，不扫描所有消息寻找肯定词。
- 必须存在已完成的正式项目快照工具调用和结果，匹配 project ID/root、revision、当前视觉合同与所有请求证据；确认前的最后一条 assistant 最终消息必须展示同一合同/revision 和 G3 意图。
- 用户消息必须晚于该快照和审核说明，直接且无条件地接受；否定、引用、嵌入内容、普通继续、重复消息、撤回和过期版本拒绝。缺引用/核验失败不自动弹表单。
- 仅接入 G3，不把视觉接受用于 Mission/G0/G4、材料授权或撤销。Node 签名和 Python 的挑战、当前证据、单次消费检查保留。
- 日志读取是本机单用户信任边界内的确认适配，不防御恶意本机程序重写 Codex 日志，不宣称独立密码学宿主证明。遇到不支持的日志格式失败关闭。
- G3 通过后继续冻结视觉上游和 anchors。build-native-first 是锚点生产入口，不是最终交付入口；不能为构建整套 PPTX 放宽所有视觉写入保护。
