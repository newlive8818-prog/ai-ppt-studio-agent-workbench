## 3. 产品定义

### 3.1 一句话定义

构建一个运行在 Codex 内、以对话为主要入口、以按需 HTML 为视觉决策界面、以本地受管工作区为状态载体、以 GPT-5.6 和 Image 2 为现成智能能力、以 Codex 自带 Presentations 为 PPTX 执行能力，能够完成内容蓝图、视觉构想、工程实现、可编辑 PPTX 生成与编辑、真实渲染验收和个人经验进化的可安装 Skill App。

### 3.2 产品不是

- 不是原 Web 产品的缩水替代品；
- 不是一个巨型提示词；
- 不是静态 PPT 模板库；
- 不是依靠整页位图伪装可编辑的 PPT 生成器；
- 不是需要账号、云端数据库和独立后端才能运行的 SaaS；
- 不是可以静默修改用户原始材料或现有代码仓库的自动化脚本；
- 不是一次项目反馈就自动改写全局规则的自修改系统；
- 不是与 Codex Presentations 并行建设的第二套 PPT 编辑器或通用编译引擎。

### 3.3 MVP 成功结果

使用一个真实售前解决方案项目，端到端完成：

1. 汇报任务与材料理解；
2. 内容蓝图与真实材料引用冻结；
3. 高质量视觉构想和可比较概念样张；
4. 一张视觉高难页和一张内容复杂页的真实可编辑工程样张；
5. 视觉合同和最小可用 Slide Scene Graph；
6. 整套可编辑 PPTX；
7. PowerPoint 真实渲染、差异诊断和修复；
8. 用户选择、否决、修改和工程掉级的完整反馈记录；
9. 至少形成一条未越权晋级的候选经验。

## 4. 已确认产品边界

### 4.1 一期包含

- 单人、本地、Codex 内使用；
- 项目材料由用户主动提供，AI 不主动搜索互联网；
- 支持文件、目录、链接、文字、图片和截图等用户输入；
- 对话承担目标补充、解释、修改和流程推进；
- HTML 承担复杂视觉比较与集中审阅；
- GPT-5.6 主导内容理解、视觉构想、评审和修复；
- Image 2 作为默认视觉合作者之一；
- 不为 Image 2 单独设置材料隐私分级、脱敏或产品阻断门槛；用户主动提供的项目材料可以按视觉任务需要使用；
- Codex 自带 Presentations 是 PPTX 读取、创建、编辑、渲染和检查的统一执行能力；
- 场景图、真实素材和原生 PPT 共同承担实现；
- 分层混合可编辑 PPTX；
- 真实渲染和全页验收；
- 项目记忆、个人偏好、失败记忆和候选经验；
- 可安装和可迁移的 Skill App 包。

### 4.2 一期不包含

- 独立 Web 前端、账号、登录和云端后台；
- 多用户、多人审批、共享项目和组织权限；
- 计费、云端任务调度和模型网关；
- 自建基础图像模型；
- 跨用户共享私人经验；
- 自动向长期 Web 产品设计回写；
- 自动将个人反馈发布为所有安装者的公共经验；
- 在任意 Codex 当前目录中自动创建隐藏运行状态。

## 6. 文件安全与导入规则

### 6.1 原始材料策略

采用“只读引用 + 按需复制导入 + 输出完全隔离”：

1. 用户主动选择文件、目录、链接、文字或图片；
2. 系统建立来源记录、内容哈希、读取时间和使用范围；
3. 只需读取的材料保留只读引用；
4. 需要转换、裁切、OCR、拆页或标注的材料复制到受管项目目录；
5. 系统不得覆盖、重命名、移动或删除原始文件；
6. 不创建指向原始资料的可写软链接；
7. 所有中间文件、HTML、样张、PPTX 和渲染结果写入受管项目目录；
8. 正式交付可以由用户明确选择复制到其他输出位置。

### 6.2 保护根目录

运行时维护 `ProtectedRoot` 清单，至少包括：

- 上游 Web 产品目录；
- Skill App 源码仓库；
- Codex 安装目录；
- 用户明确标为原始材料库的目录；
- 当前机器上的其他用户指定保护目录。

任何写操作在执行前必须解析真实绝对路径，并验证目标不位于保护根目录。无法解析、路径冲突或目标过宽时必须停止，不得猜测。

### 6.3 初始化行为

用户即使在上游 Web 产品目录或客户资料目录中触发 Skill，系统也只能：

1. 读取必要上下文；
2. 提示将在独立工作区创建受管项目；
3. 生成安全项目名称和唯一项目 ID；
4. 在受管运行根目录创建项目；
5. 将来源以只读引用或受管副本接入；
6. 不在当前目录写入 `.ai-ppt` 或其他隐藏状态。

## 8. 四个核心运行引擎

### 8.1 编排与状态引擎

负责：

- 创建和恢复项目；
- 识别当前 G0–G4 状态；
- 只提出当前最高影响问题；
- 调用内容、视觉、实现、验收和经验模块；
- 保存版本、差异、冻结和重新打开范围；
- 阻止越级执行和保护目录写入。

### 8.2 视觉构想引擎

输入：冻结内容蓝图、听众、决策目标、真实素材、品牌和 PowerPoint 边界。

输出：

- `VisualBrief`；
- 2–3 个真实不同的概念领地；
- Image 2、场景图、真实素材和原生 PPT 的介质路由；
- `ConceptSampleSet`；
- 模型自评、方向差异和风险说明；
- 用户反馈解释和受控修订版本。

不得：

- 只换颜色和字体冒充新方向；
- 用无关占位内容制造视觉效果；
- 把 Image 2 位图当作最终 PPT 对象结构；
- 为视觉效果改变冻结事实。

### 8.3 可编辑实现编排引擎

输入：冻结内容、主视觉方向、视觉合同候选和真实素材。该引擎负责把这些权威输入交给 Codex Presentations，并保存真实 PPTX 的修改、渲染和验收结果；不自行替代 Presentations。

输出：

- 最小可用 `SlideSceneGraph / SlideSpec`；
- 对象级原生、优先原生、可控位图和禁止实现路由；
- 一张视觉高难工程样张；
- 一张内容复杂工程样张；
- PPTX、真实渲染、差异诊断和修复记录；
- 整套 PPTX 和交付验收结果。

必须保证：

- 事实文字、数字、图表、表格和关键关系保持原生；
- 复杂艺术层允许高质量、可替换、可裁切、可追溯位图；
- 不用整页位图伪装可编辑；
- 工程样张通过后才能冻结视觉合同；
- 全页真实渲染通过后才能交付。

### 8.4 评估与进化引擎

负责：

- 记录用户选择、否决、犹豫、修改和最终接受；
- 记录概念样张到工程样张的掉级原因；
- 保存修改前后版本和结果；
- 提炼带场景边界的候选经验；
- 在后续相似项目中调用候选经验；
- 根据结果晋级、降级、隔离或废弃；
- 保护客户隐私和不同安装者的个人经验边界。

不得直接自动修改稳定能力内核或入口 `SKILL.md`。

## 9. 知识自循环

### 9.1 四层知识

| 层级 | 内容 | 默认写入方式 | 可否自动晋级 |
|---|---|---|---:|
| 稳定能力内核 | 事实保护、状态门、双样张、场景图、可编辑和渲染验收 | 版本发布 | 否 |
| 项目记忆 | 当前任务、反馈、版本、失败和结果 | 运行时自动记录 | 只在项目内 |
| 个人偏好与场景经验 | 多项目重复出现的有效偏好和机制 | 模型提炼、验证后写入 | 可受控晋级 |
| 公共发行经验 | 去除私人数据、跨用户验证的稳定机制 | 产品版本发布 | 否，需发布治理 |

### 9.2 经验循环

```text
原始项目事件
-> 模型解释反馈原因
-> CandidateExperience
-> 绑定场景、听众、页面任务和实现条件
-> 在后续相似任务中受控调用
-> 比较是否减少否决、返工或工程掉级
-> 晋级 / 降级 / 隔离 / 废弃
```

### 9.3 候选经验最小字段

- `experience_id`；
- 来源项目和来源事件；
- 经验类型：失败、偏好、视觉机制、实现策略、修复策略；
- 适用场景、听众、页面任务和内容条件；
- 原始反馈和模型解释；
- 修改前后引用；
- 支持证据和反例；
- 调用次数、成功次数和最近验证时间；
- 当前等级和置信度；
- 隐私级别和可移植范围；
- 版本、废弃和回滚信息。

### 9.4 防污染规则

1. 一次个人反馈只能成为项目偏好或候选经验；
2. 正向案例先进入隔离灵感池；
3. 模型提炼视觉机制，不复制具体作品；
4. 没有后续结果验证不能晋级为稳定场景经验；
5. 每条经验保留适用范围和反例；
6. 经验冲突时优先保留上下文，不强行合并为通用规则；
7. 客户名称、内容、材料和图片不得进入公共发行经验；
8. 稳定能力内核只能通过版本化产品更新改变；
9. 所有经验可查看来源、禁用、删除和回滚；
10. 插件重装不能删除个人经验，项目删除也不能静默删除已晋级经验。

任何状态门失败只重新打开受影响范围，不静默重写已确认部分。

## 11. 视觉辅助页面

MVP 不建设固定八模块 Web 工作台，只按决策需要生成四类本地 HTML：

1. 内容蓝图集中审阅页；
2. 视觉方向与概念样张比较页；
3. 概念样张、场景图与工程样张对照页；
4. 整套 PPT 渲染问题和交付验收页。

页面必须：

- 离线可打开；
- 显示项目、版本、状态门和来源；
- 支持明确选择、否决和自然语言修改入口；
- 不成为第二套独立业务数据库；
- 不把自动生成的界面文案当作权威内容；
- 所有正式结果回写受管项目对象和版本文件；
- 可被删除并从项目状态重新生成。


| 异常 | 系统行为 | 恢复方式 |
|---|---|---|
| 当前目录属于保护根目录 | 禁止当前目录写入 | 在受管根目录新建项目 |
| 运行根目录配置无效 | 不创建任何项目文件 | 要求选择独立绝对路径 |
| 原始材料不可读 | 保留来源记录和失败原因 | 用户重新授权或换源 |
| 导入部分失败 | 不删除已成功材料 | 单项重试并显示缺失影响 |
| Image 2 不可用 | 不伪造视觉结果 | 保存状态，允许稍后重试或改用可控场景图 |
| Presentations 创建或编辑失败 | 保留 Scene Graph 和日志 | 局部重试，不重做内容和构想 |
| Presentations 渲染不可用 | 阻断 G2/G4 | 恢复渲染能力后继续 |
| 用户反馈含义不清 | 不大范围修改 | 只追问一个高影响问题 |
| 经验与当前项目冲突 | 不强制应用 | 降低权重或限定在原场景 |
| 项目中断 | 保存最近成功状态 | 下次从状态门和版本恢复 |
| Skill 更新 | 先做结构兼容检查 | 迁移副本、验证后切换，失败则回滚 |

## 15. 验收标准

### 15.1 隔离验收

1. 上游 Web 产品目录在运行前后无新增、修改或删除；
2. 原始材料的文件哈希在运行前后保持一致；
3. 不在当前调用目录创建隐藏状态；
4. 所有运行文件位于受管项目目录；
5. 安装目录删除后，项目和个人经验仍完整；
6. 没有写入型软链接指向上游或原始材料；
7. 路径解析失败时不执行写操作。

### 15.2 核心能力验收

1. G0–G4 状态可恢复、可追溯、不可静默越级；
2. 内容、视觉和实现使用同一冻结事实；
3. 概念方向至少存在结构性差异；
4. 两类工程样张由 Codex Presentations 生成，真实可编辑并完成渲染检查；
5. 视觉焦点、阅读顺序、空间关系和情绪没有明显掉级；
6. 事实文字、数字和关键关系保持原生；
7. 整套每页经过真实渲染检查；
8. HTML 决策页可从项目状态重新生成；
9. 交付包包含 PPTX、来源说明、渲染结果和版本信息。

### 15.3 自循环验收

1. 用户自然语言反馈被保存为原始事件；
2. 模型解释与原始反馈分离保存；
3. 候选经验具有范围、证据、反例、版本和隐私级别；
4. 一次反馈不会自动改变稳定能力内核；
5. 后续项目可以调用或禁用候选经验；
6. 调用结果能够反向更新经验等级；
7. 私人项目内容不能进入公共发行包。

### 15.4 可安装性验收

1. Skill 目录通过结构与元数据校验；
2. 全新 Codex 环境安装后能够识别入口；
3. 首次运行明确检查必需工具和可选工具；
4. 缺少可选能力时给出可恢复路径；
5. 用户可以配置独立运行根目录；
6. 不依赖当前开发仓库才能完成真实项目。
