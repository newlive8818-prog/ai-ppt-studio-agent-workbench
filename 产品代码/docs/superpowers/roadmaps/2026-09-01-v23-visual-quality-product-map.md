**日期：** 2026-09-01

**状态：** 基于已批准设计规格形成的研发规划；不是机制已实现、样本已验证、PowerPoint 已检查或用户已认可的事实

**权威设计：** [v2.3 视觉质量与设计感攻关设计规格](../specs/2026-09-01-v23-visual-quality-semantic-compilation-design.md)

## 1. 产品目标

v2.3 不重做 v2.2 已冻结的工程治理链，而是在其上建立一条可验证的视觉语义编译闭环：让页面主张、读者判断和信息关系真正决定构图、对象、图像与原生 PowerPoint 实现，并通过真实样本、目标 PowerPoint 和用户判断证明结果。

产品目标不是“生成更漂亮的模板”，而是回答五个连续问题：

1. 这套 PPT 为什么需要采用某种视觉立场与跨页节奏；
2. 每页五秒内要让读者形成什么判断；
3. 页面主体用什么信息关系和视觉机制支持该判断；
4. 这些设计语义如何无损转为原生可编辑 PPTX；
5. 哪些机制经过真实样本和用户结果后可以复用。

## 3. 六类缺口到产品能力的映射

| 缺口 | 当前风险 | v2.3 产品机制 | 首轮证明方式 |
|---|---|---|---|
| 产品机制缺口 | 已有视觉对象，但缺少从判断到实现的正式链 | 三层视觉合同 + 确定性 `VisualCompilationPlan` | 两页合同与编译计划闭合，lineage 可追溯 |
| 设计知识缺口 | 字段能描述外观，不能指导为什么选某种构图 | 信息关系、视觉机制、图像角色、密度与强调预算 | 第 5、8 页采用不同机制且能解释选择理由 |
| 页面生成策略缺口 | 内容类型直接匹配常见组件或页面家族 | `主信息关系 → 视觉机制 → 对象计划` | 页面不从模板名起步，禁止平均卡片和等权流程 |
| 审美审查缺口 | 自动化通过仍可能廉价、弱焦点、模板化 | 五秒测试 + 20 类反模式 + 具体区域证据 | 人工结果绑定页面、版本、失败原因和修复机制 |
| 原生 PowerPoint 缺口 | 设计意图在 handoff 中丢失或被位图化 | 编译计划 + Presentations handoff + 降级策略 | 相同 PPTX 的对象、编辑性、字体、连接器和渲染证据 |
| 真实用户验收缺口 | 代码、测试和渲染被误当可交付 | 五层证据账本 + 样本退出条件 | 用户看到真实页面并将判断绑定到当前 PPTX 哈希 |

## 4. 核心产品对象及职责

### 4.1 Visual Brief：整套设计立场

负责受众、决策任务、设计立场、情绪和品牌边界、密度策略、总体图像／图示语言、全 Deck 禁止模式与五秒测试口径。它不决定每一页的具体坐标，也不保存第二套内容事实。

### 4.2 Deck Design System：跨页一致性与变化规则

负责构图语法、栅格、间距、字体、色彩、强调预算、密度节奏、图像／图示语言、页面家族适用条件、原生／位图路由、可编辑规则和跨页变化。它不是模板库，也不要求所有页面轮廓相同。

### 4.3 Slide Visual Contract：逐页设计判断

负责把冻结内容转成页面级视觉语义：五秒读者判断、主／辅助关系、视觉机制、视觉重心、资产角色、阅读顺序、文字密度、前后页节奏、PowerPoint 实现要求、反模式和验收证据计划。它不能改写 G0 冻结事实、文案、数据、来源或讲解备注。

### 4.4 VisualCompilationPlan：确定性派生的实现协议

负责把当前三层视觉合同编译为对象角色、连接语义、资产计划、布局约束、原生／位图路由和 PowerPoint 约束。它是不可变派生 artifact，不是第四套设计真相，不是用户表面，也不能自行通过任何 Gate。

首轮锁定采用“原子确定性派生”：注册新的当前 `VisualContractSet` 时，由服务端在同一事务中写入：

```text
visual/contracts          -> visual-contract-set
visual/compilation-plan   -> visual-compilation-plan
```

相同规范化输入与相同编译器版本必须产生相同 payload 和 artifact ref。模型不得独立提交另一份 compilation plan。

### 4.5 SampleEvidencePackage：样本证据账本

首轮不新增第三套 Runtime 经验库。样本证据包以项目内证据集合组织原始页、合同、编译计划、生成 PPTX、自动化结果、人工审查、目标 PowerPoint 结果、用户判断、修订记录和经验去向。

## 5. 产品流程与用户决策点

```text
已冻结内容
  ↓
Visual Brief
  ↓
Deck Design System
  ↓
Slide Visual Contract
  ↓  服务端原子派生
VisualCompilationPlan
  ↓
Codex Presentations 原生实现
  ↓
自动化检查
  ↓
五秒测试／反模式人工审查
  ↓
目标 macOS Microsoft PowerPoint 检查
  ↓
用户视觉判断
  ↓
same-type 经验候选或不入库理由
```

用户不需要批准低风险字段生成或内部编译步骤。用户决策点仍只发生在已确认的高影响选择、视觉结果判断和后续扩展授权上。首轮两页未获用户认可时，不进入正式样本扩展。

## 6. 五层证据模型

| 层级 | 能证明什么 | 明确不能证明什么 |
|---|---|---|
| E1 机制实现 | 代码、对象、服务、投影或流程已经存在 | 测试通过、样本有效、PowerPoint 可用、用户认可 |
| E2 自动化验证 | 合同、lineage、构建、结构、布局、渲染等检查通过 | 设计高级、五秒判断正确、真实售前可用 |
| E3 真实 PPT 样本验证 | 机制在批准样本上实际运行并留有前后证据 | 目标 PowerPoint 稳定、用户认可、全量适用 |
| E4 目标 PowerPoint 检查 | 相同 PPTX 在 `macos-powerpoint` 中显示、编辑、字体与布局成立 | 用户喜欢或愿意交付、deferred 目标兼容 |
| E5 用户视觉认可 | 用户看过当前页面并明确接受其视觉方向或质量 | 自动成为全局经验、正式 G4 或所有场景可用 |

每一条产品状态必须明确属于哪一层，不得以“已完成”“已通过”省略证据身份。

## 7. 首轮产品范围

### 7.1 两页机制实验

- 第 5 页：图像主导的复杂关系表达，验证 `system-boundary + network`；
- 第 8 页：原生结构主导的流程／架构表达，验证 `sequence + evidence-to-judgment`。

两页必须采用不同的视觉机制。第 5 页不能退化为等距节点流程；第 8 页不能依赖大图掩盖工程关系。

### 7.2 首轮不扩展

- 不改完整 27 页；
- 不把分享型样本当真实售前正式验收；
- 不推进原 v2.2 Runtime 项目的 G3/G4；
- 不新建模板市场、素材市场或第二个 PPTX 编译器；
- 不把非强制设计哲学改成固定问卷、字号规则或电影镜头模板；
- 不公开发布插件。

## 8. 反模式治理

20 类反模式继续以已批准设计规格为唯一目录。产品层只要求每条记录包含：

```text
pattern_id
trigger_condition
observed_region
evidence_refs
allowed_exception
repair_mechanism
result: passed | failed | not-applicable
```

审查不能只返回总分。自动化只能处理可证部分；“廉价感”“视觉张力”“图片叙事力量”和“真实售前适用性”必须保留为人工／用户判断。

## 9. 产品阶段与退出条件

| 阶段 | 产品结果 | 退出条件 | 未通过时 |
|---|---|---|---|
| V0 合同可执行性 | 两页三层合同和编译计划闭合 | 判断、关系、机制、重心、对象、反模式和证据计划完整且未改写内容 | 停在合同层修订，不做 PPTX |
| V1 原生实现 | 两页原生可编辑实验 PPTX | 语义对象原生、图片独立、自动结构／布局／渲染通过 | 修复 handoff 或实现约束，不扩页 |
| V2 人工与目标环境 | 五秒、反模式与 macOS PowerPoint 结果 | 判断一致、无未处理首要反模式、目标环境编辑和显示成立 | 保留失败版，定向修订 |
| V3 用户判断 | 当前 PPTX 的接受／拒绝／修改结论 | 用户结果绑定 PPTX 哈希、页码和版本；经验有边界 | 未认可则禁止正式扩展 |
| V4 正式样本扩展 | 3–5 个真实售前样本的新计划 | 仅 V0–V3 全部满足后由用户另行批准 | 不创建计划、不创建 Worktree |

## 10. 用户表面边界

Codex 对话仍是唯一主入口；视觉专业审核页仍保持已验收的单顶栏、双视图、锚点内联反馈、左目录覆盖和右标记覆盖结构。

v2.3 首轮 UI 只允许增加具有用户审核价值的合同正文和字段标签：

- Visual Brief 中的设计任务和边界；
- Deck Design System 中的节奏、强调、图像／图示语言和五秒规则；
- Slide Visual Contract 中的读者判断、关系、机制、重心、资产角色、节奏、密度、PowerPoint 约束和证据计划。

`VisualCompilationPlan` 不作为用户可见模块，不显示技术 lineage 账本，不建设新工作台，也不改变已验收交互结构。

## 11. 经验沉淀边界

首轮复用 `same-type | global` 两层经验：

- 只有具体页面中的可观察机制、前后差异和用户结果才能成为 `same-type` 候选；
- 自动化通过、AI 自评或抽象哲学不能成为“成功经验”；
- 客户事实、数字、Logo、文件、整页作品和未授权素材不能跨项目复用；
- 只有用户明确声明全局适用，或至少两个不同 type signature 的真实成功证据满足现有规则，才进入 `global`；
- 任何经验必须有适用范围、反例、失败边界和回滚路径。
