# AI PPT Studio v1.5 三表面研发验收记录

## 1. 验收结论

本轮按 v1.5 权威基线完成了 Codex 聊天、轻量 Native Widget 与内容/视觉专业审阅页的运行时垂直切片。验收覆盖同一项目真相源、共享 revision、专业审阅完整投影、ReviewMarkSet 显式保存、G0/G3/G4 用户聊天确认、G1/G2 内部质量门、目标渲染证据身份、聊天交付回执和三类响应式界面。

验收只证明当前代码合同和确定性临时项目可运行，不把以下事项扩大为已验证结论：Codex 长期固定右侧浏览区能力、真实聊天文件发送宿主回执、60+ 页性能、跨项目视觉稳定性、Windows/WPS 兼容性。目标 PowerPoint 的真实实机证据仍以 [严格路线 B 与 PowerPoint 目标渲染验证记录](./validation/2026-08-06-strict-route-b-powerpoint-target-render-validation.md) 为准；本页的隔离 smoke project 只验证 `TargetRenderEvidence` 的系统合同和 Gate 行为。

## 3. 已验收的运行时合同

### 3.1 Python 领域层

- 内容与视觉投影使用不可变产物种类、版本和 SHA 生成稳定 `sourceVersion`。
- 内容投影完整包含整套概览、章节、每页标题、完整可见文案、讲解稿、材料和来源。
- 视觉投影完整包含 Deck Design System、每页内容身份、视觉合同、来源、备注和规则字段。
- ReviewMarkSet 支持页面、字段和选中文字标记；保存后进入 `saved / pending-governance`，不改变 Gate。
- `expectedRevision` 冲突和源版本过期分别返回 `REVISION_CONFLICT`、`REVIEW_SOURCE_STALE`，失败不丢草稿或上一有效版本。
- G0/G3/G4 只接受带 `userMessageRef` 的聊天确认；G1/G2 只接受授权内部角色记录。
- G2 需要独立审美审查、PPT 工程审查和已通过的 TargetRenderEvidence；G4 还需要可编辑交付物和成功的 PPTX ChatDeliveryReceipt。
- 聊天发送失败只记录/重试消息，不重新构建或替换不可变交付物。

### 3.2 MCP Server

MCP 提供两个自包含资源：

- `ui://ai-ppt-studio/workbench.html`
- `ui://ai-ppt-studio/review.html`

v1.5 新增/收口工具包括：

- `render_ai_ppt_review`
- `save_review_marks`
- `get_delivery_status_projection`
- `record_chat_delivery`
- `record_internal_gate`
- 受限的 `confirm_ai_ppt_gate`

`structuredContent` 与 `_meta.widgetData` 使用同一 project revision；专业审阅保存工具只对 App 可见，且不具备 Gate 副作用。

### 3.3 React 表面

- Widget 在 360–480px 只显示五个认知空间的轻量结论、风险、成果和一个主操作。
- Widget 不显示完整蓝图、完整视觉合同、联系表、大图质检、下载区、旧 G1/G2 用户确认或独立 UI-05 验收按钮。
- 内容/视觉共用专业审阅页，Header 固定为 64px 单行，目录默认关闭。
- 左侧目录与右侧标记抽屉采用覆盖层、互斥打开，均不改变正文几何。
- 正文连续展示全部字段，不使用省略号、行数裁切或横向滚动承载完整内容。
- 页面支持字段、区块和选中文字草稿；只在点击右上角 `保存标记` 时批量持久化。
- revision 冲突和保存失败保留未保存草稿；页面没有返回聊天、顶部版本历史、样张画廊、Gate 或 PPTX 下载入口。

## 6. 保留的待验证项

- Codex 当前及后续版本能否长期保持右侧宿主浏览区，以及独立页面降级的宿主级打开行为。
- Codex 真实发送本地样张/PPTX 后可获得的宿主消息引用、失败重试和用户结果回执能力。
- 60+ 页内容/视觉投影的渐进渲染、目录定位和批量标记性能。
- 严格路线 B 的跨项目视觉稳定性、完整长篇方案表现。
- PowerPoint for Windows 字体替代与几何一致性；WPS 仍是独立兼容目标，未形成实机证据前不声明兼容。

这些项目保持 `待验证`，不影响当前 v1.5 本地运行时与三表面合同的研发落地结论。
