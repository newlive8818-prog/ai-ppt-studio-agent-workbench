## 2. UI 的核心命题

这不是给人手工操作所有流程的传统软件，也不是静态前端展示。UI 必须同时完成三件事：

1. 把 AI 的任务模型、事实、推论、决定、不确定性和成果外化给人；
2. 把人的选择、反馈和确认结构化回写给 AI；
3. 在动态对话和不确定推理中提供稳定的认知空间、状态、版本与质量边界。

UI 的成功不是“页面漂亮”，而是用户能用更少认知负担判断 AI 是否理解正确、是否在轨、是否需要干预，以及最终交付物是否值得接受。

## 3. 设计原则

1. **结论优先**：首屏顺序固定为当前结论 → 风险/缺口 → 下一步 → 证据。
2. **一个主动作**：每个视图只允许一个最强视觉主操作。
3. **AI 认知可见**：事实、推论、建议、决定、不确定性和成果不能混成普通文本。
4. **稳定容器，动态内容**：五个空间稳定，页面内部由 Agent 按项目状态动态生成。
5. **紧凑不是缩小网页**：窄视图只保留认知主线和当前判断。
6. **证据就近**：结论附近可以查看依据、版本和影响，不要求跨页记忆。
7. **判断优于编辑**：页面适合选择、确认、否决、撤销；复杂修改通过 Codex 对话。
8. **密度服务比较**：材料和逐页蓝图使用高效列表/表格，不做卡片墙。
9. **过程可恢复**：AI 长任务显示阶段、已完成成果、失败和重试，不显示空白 spinner。
10. **高影响清晰**：冻结、交付、删除和改变事实必须说明后果。
11. **不暴露思维链**：展示外化判断、依据和影响，不展示隐藏推理过程。
12. **专业来自精确**：有限配色、一致图标、清晰层级、真实内容和克制动效优先于装饰。

## 4. 页面体系

### 4.1 一级导航

固定顺序：

1. 项目总览；
2. 材料工作台；
3. 内容蓝图；
4. 视觉设计；
5. 制作与交付。

导航不显示数字步骤，不使用“下一步才能解锁”的向导感。未到达的空间可显示状态但不可伪造空页面；点击时解释前置条件。

### 4.2 全局页面骨架

```text
┌─────────────────────────────────────────────────────────────┐
│ Project Header：页面 / 项目 / AI 状态 / 帮助 / 更多          │
├──────────┬───────────────────────────────┬──────────────────┤
│ Stable   │ Main Decision Surface         │ Context Inspector│
│ Nav      │ 结论、工作对象、比较与证据     │ 当前焦点、影响、  │
│          │                               │ 下一步、对话入口  │
├──────────┴───────────────────────────────┴──────────────────┤
│ Optional fixed delivery/action bar                          │
└─────────────────────────────────────────────────────────────┘
```

右侧 Inspector 仅在需要对选中对象做判断时出现；不是每页都必须占满右栏。

## 5. 响应式产品形态

### 5.1 紧凑 Native Widget

- 目标宽度：360–480px；
- 目标：随 Codex 对话快速查看和判断；
- 不显示完整左导航文字、复杂表格和大样张；
- 以一条纵向认知主线展示：
  1. 交付目标；
  2. AI 当前判断；
  3. 当前焦点/不确定性；
  4. 受影响成果；
  5. 当前需要的一个判断；
- 主操作：`回到 Codex 对话` 或 `提交当前判断`；
- 次操作：`展开完整工作台`；
- 显示项目名、同步状态、当前空间图标和未处理高影响项数量；
- 内容超过一屏时优先折叠证据，不隐藏结论和主操作。

### 5.2 全屏工作台

- 设计基准：1440×1024；
- 最小正式验收宽度：1080px；
- 左导航：220–240px；
- 主内容：弹性宽度；
- 右侧 Inspector：280–336px；
- 页面边距：24–32px；
- 三栏不够时，Inspector 降级为抽屉，不压缩主工作区到不可读；
- 不把整个应用放进居中浮卡；基础页面表面就是应用表面。

### 5.3 宿主能力降级

- 无 fullscreen：在 inline 内提供“打开离线审阅页”或回到对话；
- 无 sendMessage：保存意图后显示“已保存，请返回对话继续”；
- 无 updateModelContext：不影响持久写入，只降低即时上下文同步；
- Widget 重挂载：重新读取项目投影，不依赖 localStorage 恢复业务状态。

## 6. 视觉语言

### 6.1 活跃方向

`可信、专业、现代但克制的企业 AI 工作台`。

- 运营页面以白色和冷灰为主；
- 紫色表达 AI、生成、当前焦点和智能动作；
- 蓝色表达用户事实与来源；
- 绿色表达人工确认和通过；
- 琥珀色表达不确定性、待处理和可控风险；
- 红色只表达阻断、错误和高风险；
- PPT 样张区域可以丰富，但不得污染产品 UI 的状态语义。

### 6.2 颜色 Token

| Token | 建议值 | 用途 |
|---|---|---|
| `surface/base` | `#FFFFFF` | 主表面 |
| `surface/subtle` | `#F7F8FC` | 页面背景、分区 |
| `surface/selected` | `#EDE9FF` | 选中态、AI 轻背景 |
| `text/primary` | `#172033` | 主文字 |
| `text/secondary` | `#667085` | 说明文字 |
| `border/default` | `#E6E9F2` | 1px 分隔 |
| `ai/primary` | `#5B3DF5` | AI 主动作、当前焦点 |
| `fact/primary` | `#3E63DD` | 用户事实、来源 |
| `confirmed/primary` | `#079455` | 已确认、通过 |
| `uncertain/primary` | `#DC6803` | 不确定性、待判断 |
| `danger/primary` | `#D92D20` | 阻断、失败、破坏性 |

研发可为可访问性调整具体值，但不得改变语义映射。状态必须同时使用文字、图标或形状，不只用颜色。

### 6.3 字体与字号

- 字体栈：`PingFang SC, Microsoft YaHei, system-ui, sans-serif`；
- 数字可继承系统字体，不额外引入不稳定网络字体；
- Page title：20–24px / 600–700；
- Section title：16–18px / 600；
- Body：14–16px / 400–500；
- Dense table：12–14px；
- Supporting text：12–13px；
- 行高：正文 1.5–1.7，表格 1.35–1.5；
- 不以浅灰小字承载关键事实或主要操作。

### 6.4 间距、圆角与边界

- 基础间距：4px；常用 8/12/16/24/32；
- 主区块圆角：10–12px；按钮 8–10px；标签 999px；
- 分组优先顺序：邻近 → 对齐 → 留白 → 背景 → 1px 边界 → 阴影；
- 阴影只用于真正悬浮的菜单、抽屉或模态层；
- 禁止卡片套卡片和每行一个卡片；
- 密集列表优先共享表面和行分隔。

### 6.5 图标

- 使用一套线性图标族；
- 统一 1.5–2px 描边、圆角和 20/24px 盒；
- 频繁操作保留文字标签；
- AI、事实、决定、不确定性和成果使用稳定图形语义；
- 禁止用陌生品牌图标表达常规操作。

## 8. 状态语义

| 状态 | 文案前缀/标签 | 颜色 | 必需信息 |
|---|---|---|---|
| 用户事实 | `事实` / `用户提供` | 蓝 | 来源、版本、定位 |
| AI 推论 | `AI 推论` | 紫 | 依据、置信度、更新时间 |
| AI 建议 | `建议` | 紫 | 预期影响、是否可撤销 |
| 已确认 | `已确认` | 绿 | 确认人、时间、范围 |
| 不确定性 | `待澄清` / `不确定性` | 琥珀 | 影响和是否阻断 |
| 冲突 | `来源冲突` | 红/琥珀 | 冲突双方、推荐处理 |
| 处理中 | `AI 正在…` | 紫 | 阶段、完成度、可离开 |
| 自动修复 | `自动修复中` | 紫 | 问题、目标、上一有效版本 |
| 失败 | `失败` | 红 | 发生位置、保留内容、重试/替代 |
| 成果 | `成果` | 中性/绿 | 版本、质量门、可查看产物 |

禁止使用“AI 已理解”“AI 已完成”等无证据的空状态。

## 9. UI-00 紧凑 Native Widget

### 页面使命

让用户在不离开 Codex 对话焦点的情况下，快速知道项目当前最重要的认知状态，并处理最多一个高影响判断。

### 首屏顺序

1. 项目与同步状态；
2. 交付目标；
3. AI 当前判断；
4. 当前不确定性/焦点；
5. 受影响成果；
6. 当前判断；
7. 主操作。

### 交互

- 顶部图标切换五个空间的紧凑摘要；
- 点击节点展开一层依据，不能无限嵌套；
- 判断提交后先保存，再触发 Codex；
- `展开完整工作台` 请求 fullscreen；
- fullscreen 不可用时提供离线审阅或对话降级。

## 10. UI-01 项目总览 / AI 交付认知地图

### 页面使命

让用户理解 AI 当前如何建模这个项目，以及目标、事实、判断、决定、不确定性和成果之间的因果关系。

### 页面结构

- Header：项目、AI 当前状态；
- Main：一张连续认知地图，不是指标卡片墙；
- Inspector：当前对话焦点、为什么重要、关联节点、建议下一步；
- Footer/secondary：交付状态、版本历史和最近对话。

### 认知地图层级

```text
交付目标
  ↓
汇报对象 + 要解决的问题 + 事实与材料
  ↓
AI 当前判断
  ↓
已确认决定 + 当前不确定性
  ↓
受影响成果 + 交付状态
```

### 首次项目状态

任务书未确认时，Main 替换为自然语言理解后的确认卡：

- 给谁汇报；
- 汇报什么；
- 促成什么判断/行动；
- 当前已知材料；
- 主要限制和未知项。

同一时刻只询问一个最高影响缺口。

### 主操作

`继续与 Codex 对话`。如果当前有必须判断项，主操作改为 `处理当前判断`。

## 11. UI-02 材料工作台

### 页面使命

让用户把所有可用材料交给系统，并知道 AI 如何分类、提炼和判断，而不是要求用户维护上传目录。

### 首屏结论

一句话显示：材料数量、分类完成、权限问题、内容冲突和需要补充的关键证据。

### 页面结构

1. 统一输入区：
   - `选择文件或文件夹` 为主；
   - `粘贴文字`、`添加链接` 为次；
   - 建议标签仅帮助回忆，不是必填清单。
2. 材料列表：
   - 名称/来源；
   - AI 识别用途；
   - 提炼结果；
   - 状态；
   - 来源与追踪；
   - 一个默认行操作“查看”。
3. Inspector：
   - 分类分布；
   - 提取事实、案例、截图；
   - 冲突和缺口；
   - 明示“AI 不主动外部搜索”。

### 状态

- 等待上传；
- 正在读取；
- 部分解析；
- 已分类可用；
- 待授权；
- 链接失效；
- 存在冲突；
- 低置信度用途；
- 重复材料；
- 来源已更新。

### 主操作

`查看 AI 提炼结果`；材料不足时为 `继续补充材料`。

## 12. UI-03 内容蓝图

### 页面使命

在任何视觉设计前，集中确认整套叙事、章节、逐页任务、逐字稿和真实材料引用。

### 视觉禁区

G0 前不得出现：

- 配色方向；
- 页面布局选择；
- 视觉样张；
- 图片处理方案；
- 视觉质量评分。

### 页面结构

1. Conclusion Strip：总页数、可确认、需材料、叙事分歧；
2. 叙事概要：目标、听众、说服主线、视角、章节逻辑；
3. 左侧章节树：章节名称、沟通任务、页数和状态；
4. 中央逐页表：页码、标题、沟通目标、核心主张/文案摘要、引用材料、状态；
5. Inspector：选中页目标、逐字稿、必须引用材料、案例/截图、缺口、下游影响；
6. 底部/固定动作：向 Codex 修改、确认本页、集中确认 G0。

### 信息密度

- 默认显示 8–12 行；
- 长文案摘要 1–2 行，完整内容在 Inspector；
- 页码、标题和状态滚动时保持可识别；
- 不把每一页做成大卡片。

### 主操作

所有阻断项解决后为 `集中确认内容蓝图`；否则主操作是处理当前最高影响问题。

## 13. UI-04 视觉设计

### 页面使命

把已确认内容转化为高质量视觉方向，并在选方向时同步证明可编辑实现，而不是先画漂亮图、后补工程。

### 页面结构

1. 策略条：听众、预期调性、品牌/环境、可编辑目标；
2. 大型代表样张：明确标记 `Image 2 视觉构想` 或 `PPTX 工程样张`；
3. 方向选择：2–3 个结构性不同的命题，不只换色；
4. 关键样张验证：封面、视觉叙事页、内容复杂页；
5. Inspector `视觉与实现合同`：
   - 听众适配；
   - 构图与视觉语法；
   - 字体和色彩；
   - 图片/图示/图表策略；
   - 原生 PPT 实现；
   - 可编辑对象；
   - 高风险效果；
   - 等价替代和禁用规则。

### 方向状态

- AI 探索中；
- 自评完成；
- 推荐；
- 用户选中；
- 修改中；
- 工程验证中；
- 工程失败；
- 合同可冻结；
- 已冻结。

### 主操作

- G1 前：`采用方向并进入工程验证`；
- G2 后：`冻结视觉合同`；
- 不满意时：`重新探索方向` 或 `向 Codex 提出修改`。

## 14. UI-05 制作与交付

### 页面使命

让用户判断交付物质量，而不是管理技术流水线；AI 负责构建、渲染、诊断和可撤销修复。

### 首屏结论

必须同时回答：

- PPTX 是否已生成；
- 页面是否真正可编辑；
- 视觉还原是否通过；
- 还有多少页在修复或需要判断；
- 是否达到 G4 交付门。

### 页面结构

1. Gate Strip：内容冻结、视觉合同、PPTX、渲染验收、最终交付；
2. 全稿联系表：每页缩略图和通过/修复/需判断状态；
3. 选中页大图：支持视觉构想/PPTX 渲染切换或并排；
4. Inspector `AI 交付质检`：
   - 原生对象可编辑性；
   - 字体；
   - 文本溢出与裁切；
   - 图片分辨率；
   - 对齐和间距；
   - 来源追溯；
   - 演讲备注；
   - 文件完整性；
5. 高影响判断：一次只显示一个；
6. 交付文件区：PPTX、PDF/图片预览、逐页审阅、来源清单、交付报告。

### 主操作

- 修复中：`继续自动修复`；
- G4 可通过：`完成验收并交付`；
- 发现整体问题：`向 Codex 提出整体修改`。

## 15. 对话与页面的交互合同

### 15.1 页面适合直接完成

- 选择一个方向；
- 确认/否决一个决定；
- 查看来源；
- 切换版本；
- 撤销/恢复；
- 选择当前影响范围；
- 触发一个已定义 Agent 动作；
- 进入全屏或返回对话。

### 15.2 必须进入 Codex 对话

- 描述复杂修改意见；
- 改变叙事、听众、页数或方案边界；
- 组合多个视觉方向；
- 解释为什么不满意；
- 要求 AI 重新推理；
- 处理不能压缩为 2–3 个选项的开放问题。

### 15.3 回写反馈

用户点击页面动作后：

1. 立即显示“正在保存”；
2. 保存成功显示新版本和影响范围；
3. 需要 AI 时显示“已提交给 Codex”；
4. 宿主未接收时显示明确恢复入口；
5. 失败保留用户输入，允许重试；
6. 不用成功色诱导用户接受 AI 默认建议。

## 16. Decision Panel 规范

每个高影响判断必须包含：

- 问题；
- 为什么现在需要判断；
- 影响哪些章节、页面、合同或交付物；
- AI 推荐及其理由（如有）；
- 2–3 个互斥选项；
- `向 Codex 说明其他意见`；
- 是否可撤销；
- 决定后下一步。

默认选项不得利用颜色、排序或措辞操控用户。推荐项可标记“推荐”，但所有后果必须同等可见。

## 17. 版本、差异与恢复

- 任何冻结、方向选择、整体修改和构建产生新版本；
- 页面显示最新有效版本和当前工作版本；
- 差异优先展示业务影响，不直接展示 JSON diff；
- 恢复旧版本创建一个新版本，历史不可变；
- 下游产物过期时明确显示“受上游变更影响”；
- 用户永远能回到最近一次通过质量门的版本。

## 18. AI 长任务体验

### 必须显示

- 当前阶段而不是笼统“处理中”；
- 已完成/总数；
- 已经产出的可查看成果；
- 是否可以离开；
- 失败位置；
- 保留了什么；
- 重试、取消或等待用户的下一步。

### 禁止

- 全屏阻塞 spinner；
- 隐藏已完成结果；
- 把普通生成结果变成大量待办通知；
- 用虚假的百分比制造精确感；
- 任务失败后清空原页面。

## 19. 空、错误与边界状态

### 19.1 空状态

- 项目未建立任务：解释最低必需信息并进入对话；
- 无材料：显示统一输入和建议类型；
- 蓝图未生成：说明 AI 正在准备或缺少什么；
- 视觉未开始：说明必须先通过 G0；
- 未生成 PPTX：说明当前所处 G1/G2/G3 状态。

### 19.2 权限和失败

- 链接无法访问：保留 URL、失败原因、重试和粘贴正文入口；
- 字体缺失：显示受影响页和替代建议；
- Image 2 不可用：保留视觉任务，允许稍后重试或用场景图/原生 PPT 工程探索；
- Presentations 失败：保留上一构建和失败页；
- MCP/宿主失败：本地状态不丢，提示返回对话或重新打开 Widget；
- revision 冲突：显示双方修改范围，禁止静默覆盖。

## 20. 文案规范

- 用业务语言，不用内部实现术语；
- `AI 正在提炼材料` 优于 `Running pipeline`；
- `需要你的判断` 优于 `Pending approval`；
- `来源冲突` 优于 `Data error`；
- `上一份可用版本已保留` 比“失败”更能支持恢复；
- 不说“AI 已完全理解”，改为“AI 当前判断”；
- 不说“100% 高质量”，展示通过了哪些质量门；
- 按钮使用动词 + 结果：`确认内容蓝图`、`继续自动修复`、`完成验收并交付`。

## 21. 动效

动效只用于：

- 说明紧凑到全屏的连续性；
- 节点展开和影响路径；
- 长任务阶段推进；
- 决定保存与状态回写；
- 版本切换和差异出现；
- 成功、失败、撤销和恢复。

持续漂浮、呼吸、弹跳和无意义 hover lift 禁止进入运营页面。

## 22. 无障碍与可用性

- 正文对比度按 WCAG 2.2 AA 目标；
- 关键状态不只用颜色；
- 键盘可到达导航、主操作、表格行和 Inspector；
- 焦点可见；
- Pointer target 建议不小于 40×40px；
- 200% 缩放不丢核心动作；
- 长中文、长文件名和无空格字符串可换行/省略并查看全文；
- 图像样张有文本说明和状态；
- 实时状态更新对辅助技术可感知；
- Critical 信息不得只在 hover 出现。

## 23. 设计验收

### 23.1 3–5 秒扫描测试

每页必须识别：

1. 当前页面和项目；
2. 最重要结论、问题或风险；
3. 主操作；
4. 查看证据/历史的位置。

### 23.2 关键任务测试

1. 从 Codex 打开紧凑 Widget；
2. 理解当前 AI 判断；
3. 展开完整工作台；
4. 上传混合材料；
5. 查看 AI 分类和来源；
6. 修改并确认一个蓝图页；
7. 选择视觉方向并查看实现风险；
8. 比较概念/PPTX；
9. 处理一个交付判断；
10. 恢复上一版本。

### 23.3 真实内容测试

- 0、12、120 项材料；
- 10、24、60 页蓝图；
- 150 字标题、1000 字备注、长文件名；
- 部分链接失效；
- 关键来源冲突；
- 低置信度 AI 推论；
- Image 2 网络失败；
- PPTX 3 页修复中；
- Widget 重挂载；
- revision 冲突。

### 23.4 研发截图门

- 1440×1024 全屏 5 页；
- 360/420/480px 紧凑视图；
- 默认、加载、失败、冲突、待判断、通过状态；
- 无溢出、遮挡和不可读字号；
- 与本规范的层级、状态和主操作一致。
